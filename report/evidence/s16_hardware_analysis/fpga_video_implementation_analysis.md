## 3. 算法如何对应硬件

| 算法步骤 | 实际实现 | 视频可展示的具体内容 |
|---|---|---|
| 输入邻域与嵌入 | PS 取 7×7×270 邻域、逐窗归一化，加入可学习标记与位置编码，量化到 DDR 输入缓冲 | PS 与 PL 的边界，用一条简短输入链交代 |
| 三模积投影 | `mode1`、`mode2`、`mode3` 三个计算级，分别沿三个逻辑轴运算 | 三个计算级和级间缓冲，不只出现一个“张量投影”框 |
| 投影中的并行计算 | K7 配置的 mode3 同时更新7个位置、54个输出通道的累加器 | 7×54路乘加阵列，同拍更新多个累加器 |
| 投影级之间的流水 | `token_pipeline` 中的 DATAFLOW 与级间乒乓缓冲 | 不同颜色 token 分别占据不同计算级 |
| Q、K、V、M 投影 | 调度器依次选择投影权重，复用同一组三模积计算级 | 同一个计算核依次标为 Q、K、V、M |
| 注意力分数 | `ta_scores`，6个 token、每 token 4个特征 lane，共24路乘加 | 并行点积产生6×6分数矩阵 |
| Softmax | 行最大值、指数分段查表、串行倒数计算、乘法与移位 | 将 Softmax 展开为实际实现步骤 |
| 加权融合与残差 | `ta_ctx`，24路乘加，结果舍入饱和并与归一化输入相加，同时累计后续统计量 | 融合、残差和统计量在同一遍数据处理中完成 |
| 十二层编码 | 层计数器循环调用已有模块，中间结果保存在片上 | 层号递增、片上反馈，体现计算资源复用 |
| 分类头 | `ta_head` 读取 token 1 的2646维特征，最多24类乘加并行 | 特征广播到类别累加器，输出类别与置信度 |

M 是代码中的 `mlp` 张量投影。这里应保持本项目结构，不套用常规 ViT 的多头、缩放点积或两层 GELU MLP 示意。

## 4. 最值得放大的例子：第三模积

第三模积的核心关系是：

```text
Y[a,b,c] = Σ(j=0..53) T2[a,b,j] × W3[c,j]
```

对应 `tt_engine.cpp:215` 的 `mode3`。在稳定 K7 配置下，固定一组 a，每个 j 步骤同时执行：

```text
7个位置 b × 54个输出通道 c = 378路乘加更新
acc[b,c] += T2[a,b,j] × W3[c,j]
```

这个结构有两种复用：一个位置的数据值送给54个输出通道，同一个通道的权重送给7个位置。j 从0推进到53，逐步完成累加。

建议的动画动作：

1. 输入侧出现7个数值，权重侧出现54个权重。
2. 7×54阵列同时点亮，表示多个乘加并行更新。
3. j 计数器推进，阵列中的累加值持续更新。
4. 一组结果进入 `pend` 暂存，下一组继续累加时，上一组按每拍7个结果写出。

只需画出部分阵列单元并用省略号标明“共7×54路”，无需在屏幕上塞满378个小格。

这也能解释代码里的具体优化：舍入与饱和分散到写出过程中，每拍处理7个结果，避免组末同时设置378路舍入饱和逻辑。该策略与下一组累加重叠。

注意区分：378是该计算级的逻辑乘加并行数，不是整设计的 DSP 数，也不是每拍产生378个最终输出。54次累加也不代表整个投影只需54拍。

## 5. 存储供数与 token 流水怎样画

可以用下面的结构作为投影放大图：

```mermaid
flowchart LR
    X[片上输入分组存储] --> M1[第一模积]
    M1 --> T1[t1 乒乓缓冲]
    T1 --> M2[第二模积]
    M2 --> T2[t2 乒乓缓冲]
    T2 --> M3[第三模积<br/>7×54路乘加]
    M3 --> O[结果暂存与分拍写出]
```

分组存储需要连到并行计算单元，让观众看见“多个存储组同时供数”。文字可以写“按访问维度分组，支持多路读写”。

具体依据：

- `xb` 按 token、空间轴和配置 lane 分区。
- `t1` 按两个空间轴分区，便于第二模积同时读取所需数据。
- `t2` 按第三模积需要的访问方向分组，向位置并行通路供数。
- 第三模积权重按输出通道打包并分组保存于 URAM，64位字包含4个16位权重，K7实现用14组字阵列覆盖54个有效通道。
- 注意力块按 `[token][lane][depth]` 布局。K7时6×4个 bank 为并行点积供数。

流水动画采用不同颜色的 token：在一段重叠窗口里，token A 位于第三模积，token B 位于第二模积，token C 位于第一模积。相邻级之间显示乒乓缓冲，表达前后 token 使用不同缓冲区进行读写。

动画旁标明“token间流水示意，阶段长度不按实测比例”。不能把等宽时间格解释成每级只需一拍。实际报告中的三个计算级延迟并不完全相等。

要明确区分两层调度：投影内部存在 token 流水；整网的十二层和不同 patch 仍按稳定路径顺序推进。`TT_M3_OVERLAP=0` 关闭的是后加的投影与注意力重叠候选，并没有取消 `token_pipeline` 中原有的三模积 DATAFLOW。

## 6. 整网展开图需要表达的执行关系

PS 完成输入准备后，PL 的正常 FULL 路径按以下顺序运行：

```text
读取一个输入块并累计统计量
  每层循环，共12层：
    计算统计参数，归一化，保留归一化块 XN
    复用投影核计算 Q，存入 QB
    复用投影核计算 K，存入 KB
    根据 QB、KB 计算分数与 Softmax
    复用投影核计算 V，覆盖已用完的 KB
    加权融合，与 XN 相加，写回 X 并累计统计量
    再次归一化，保留当前 XN
    复用投影核计算 M
    M结果与当前 XN 相加，写回 X 并累计统计量
  读取 token 1，完成分类头并写结果
```

视频中可以简化标签，但需要保留这些实现特点：

- Q、K、V、M 使用同一个投影核，避免把四条分支画成四个同时运行的独立阵列。
- 层号0至11递增，计算模块复用，避免把十二层画成十二套并行硬件。
- 模型激活时装载权重，后续推理复用片上权重。
- 普通 FULL/CLASS 或 LOGITS 路径的层间结果留在片上。输入和最终结果仍通过 DDR 交换，调试输出属于额外路径。
- K 用完后，原缓冲区改存 V，这是一个可以直接做成变色动画的存储复用例子。
- 残差写回时顺带累计和、平方和，为下一次归一化提供统计量，减少额外遍历。

Softmax 的实现可以单独放大为“减去行最大值、双表计算指数、求和与串行倒数、乘法移位”。两个指数表各256项。不要把全部网络归一化统称为纯整数查表：`token_stats` 仍包含浮点平方根和除法。

## 7. 推荐替换现有30秒内容的两页分镜

算法网络页保留在前面。现有“难点列表”页改为计算数据通路页，现有 PS/PL 总览页缩短为过渡，并展开 PL 内部的复用执行页。优先把时间留给实际运算过程。

| 相对时间 | 画面 | 屏幕上的主要文字 | 观众应理解的内容 |
|---|---|---|---|
| 0–3秒 | 算法网络中的“张量投影”定位到 PL，显示 PS 输入准备的边界 | PS准备输入，PL执行编码与分类 | 算法与硬件部署位置对应 |
| 3–8秒 | 放大三模积计算级和分组存储，数据进入 t1、t2 缓冲 | 三模积三级流水，片上存储分组供数 | 算子拆成了计算级和存储结构 |
| 8–13秒 | 放大第三模积，7路位置输入与54路权重进入阵列，j推进 | 7×54路并行乘加 | 同一时刻并行计算什么 |
| 13–17秒 | 三种颜色的 token 分别占据三个计算级 | token间流水，乒乓缓冲交替读写 | 流水发生在不同 token 的计算级之间 |
| 17–23秒 | 同一个投影核依次切换Q/K/V/M，层计数器0至11递增 | 同核计算Q/K/V/M，逐层复用 | 并行计算与整网顺序调度同时存在 |
| 23–27秒 | Softmax展开为指数表与倒数，KB由K变为V | 指数查表，K/V缓冲复用 | 非线性运算与存储优化的具体实现 |
| 27–30秒 | 层间反馈仍在PL内部，最终结果写DDR并交给PS | 权重与层间结果留在片上 | 存储组织如何减少外部数据交换 |

两页标题建议：

1. **三模积投影的并行数据通路**，0至17秒。
2. **整网计算与片上存储复用**，17至30秒。

“16位权重、18位片上激活、舍入与饱和”可以作为第二页静态小字。参考验证与资源结果放在后续性能页或答辩备份，避免在30秒里增加更多切换。

如果整体视频时间允许，建议把该段放宽到40秒：增加4秒解释存储如何供数，增加6秒让观众看清 token 流水和层间复用。30秒版需要提前让观众认识三模积和 Q/K/V 的意义。
