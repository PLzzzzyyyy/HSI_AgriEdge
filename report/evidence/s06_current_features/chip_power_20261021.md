# 无外接模块的芯片功耗估算

本版取消 INA226 接入，沿用现有 FPGA 位流和推理算法。PC 与 DP 当前显示名称为“芯片参考功耗”和“本任务参考能耗”，温度仍为 PS SYSMON 的芯片内部实测温度。功耗在技术上仍为模型估算，界面保留“Vivado 模型／非实测”来源说明；没有板载电流测量，不能把本功能称为整板实时功率测量。

## 依据与局限

对当前 KEY5/KEY6 位流对应的 `build/keys_eco_20261018_v4/keys_routed.dcp` 执行 Vivado 2026.1 `report_power`，分别固定结温 -40、0、25、40、55、70、85、100、125°C。checkpoint、位流、XSA 的 SHA256 与现有硬件套件逐一核对；原始报告保存在 `report/chip_power_20261021/`。

40°C 的芯片总功耗参考值为 6.029 W。运行时使用实测结温在相邻报告点之间插值，约每秒更新。模型固定使用报告的向量无关活动假设，不根据“运行中/空闲”随意乘系数，不加入随机波动，也不以温度反推实测功率。动态项固定，变化主要反映温度对静态功耗模型的影响，不能显示真实的瞬态负载波动。

本次报告整体置信度为 **Low**，未导入 SAIF，工具还提示缺少输入活动约束以及复位活动可能影响结果。温度修正并不能消除这些不确定性。未经电流仪表校准，不提供误差百分比，不用于证明整板功耗或低功耗优化已达标。

范围为 PS＋PL 的芯片功耗模型，不包含外部 DDR 颗粒、风扇、板上外围器件、DC/DC 损耗。功耗模型的 PS DDR 接口项与外部 DDR 颗粒耗电是两个范围。

## 温度与能耗规则

- 温度有效期 3 秒；温度无效或过期时使用明确标注的 40°C 参考功耗，记录参考温度累计时长，不伪造温度。
- 估算能耗按板卡本地单调时钟对估算功率分段积分；接受 START 时清零，到 DONE、STOP 或错误时冻结。包括准备输入、暂停、显示和通信期间的时间，前置权重上传不在 START 期间。
- 后续单点探查不增加已经冻结的任务能耗；本版不提供独立单点操作的功耗积分。
- 每像素估算能耗＝任务估算能耗×1000÷板端已计算像素数。没有完成像素时不显示该指标。冷启动小任务的准备开销会使该值明显偏大，不能与纯 PL 计算能耗混为一谈。
- 估算在板卡本地累计，网页断连不改变累计规则；PC 超过 3 秒没收到估算，显示“已过期”。任务历史没有估算报文时保持无数据，不事后补造。

## 数据一致性与启动

新增独立 0x8C 报文，包含 boot/session、板端任务号、模型 ID、计数器、温度来源有效标志、估算功率、估算能耗、累计时长、参考温度时长和已计算像素数。保留原实测功率字段为空；估算使用 `power_est_w`、`energy_est_j`、`energy_est_mj_per_px`，均带 `measured=false`。

PC 验证模型、身份、范围、有限数值、单调累计和冻结状态，再将原始报文保存至任务日志。DP 直接使用同一板端对象绘制，无需 PC 回传估算值。模型 JSON 与 C++ 系数由 `tools/freeze_chip_power_profile.py` 同步生成，随主机资源和配套 ELF 一起冻结。

正常仍双击 `D:\FPGA.GAME\START.bat`。启动器从 `firmware/keys_20261018/deployment.json` 选择匹配固件及 PC 资源，无需另起一套入口。原固件保存在 `firmware/keys_20261018_before_chip_power_20261021/`。

## 重现与验证

1. 离线生成报告：`tools/report_chip_power.tcl`。
2. 冻结模型：`tools/freeze_chip_power_profile.py`。
3. C++ 检查：`tools/tests/test_chip_power.cpp`；覆盖插值、温度过期切分、任务重置、重复 START、STOP 冻结。
4. Python 检查：`tools/tests/test_board_power.py`；覆盖报文边界、模型身份、无效数值、任务隔离、单调性与冻结。
5. 画布检查：`tools/tests/render_chip_power.cpp`；验证绘制边界和局部重绘，不改变地图、分类数量和任务卡。
6. 上板记录：`report/chip_power_20261021/live_verification.json`（仅在实际验证通过后生成）。
