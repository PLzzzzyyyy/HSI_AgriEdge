## 修复

- 删除“预计剩余”：原值使用 250ms 周期的接收像素差分计算，受行包批量返回、准备和消息时延影响，没有足够依据证明剩余时间误差小于 10%。保留已处理、已用时和板端计算速度。
- 连续单击：原检查将 PC 的 `v3` 与板端包标签 `v3_board` 直接比较，误判成不同模型，下一次点击被拦。改为使用已经核验的运行身份映射。当前模型的开放探查通道复用；选择了其他模型、场景或历史任务后，若板卡空闲，则明确建立当前选择的单点任务，不要求清空界面。
- 框选工具中，单击不拖动也能直接探查；拖动才产生矩形，不额外发单点请求。多边形工具仍保留逐顶点绘制。
- 清空内容会清零并刷新 pred/conf/err/predB/diff 离屏缓存，保留原始历史数组、任务、保存地块与连接。清空后保留当前任务模式、工具、页签，不强制回整景巡检。清空后台运行的任务显示后，也隐藏它的推扫动画。

## 速度对比

1. 打开下方“速度对比”。选择 A、B 两个不同的有效板端权重。
2. 默认采用中心 32×64 区域；也可以先框选，再点“使用当前框选”。区域上限为 16,384 像素，方便短时间内完成可复现的对比。
3. 点“开始实测对比”。同一板卡依次执行 A、B，区域完全一致。图中显示真实已接收的分类像素、进度、px/s、ms/像素和任务时间。
4. 完成后显示 B/A 倍率、百分比差异和每像素时间差。“同步回放”按保存的进度点展示两个版本；可选板端累计计算时间或实际任务时间（含准备）。放大对比按钮适合录屏。
5. “停止对比”停止当前步骤，不继续下一权重。历史任务保留，比较记录保存到 `build/host/gcs_roi/speed_compare/*.json`。可从“速度对比历史”重新打开和导出。

计时来源是实际板端 STATUS 累计计算计时与完成像素数，不使用人为设置的速度系数。计算范围包含 PS 像素准备及引擎等待，不能等同于纯 PL 时间。任务墙钟时间包含准备、调度和通信；与计算速度分开展示。

所有现有权重共用同一个固定结构，因此单纯换权重可能几乎没有速度差异。差异小于 5% 时界面注明“速度接近”；不会为了制造视觉差异放慢任一版本。要有显著计算加速，需要另行实现和验证减少运算或增加并行度的算法/IP。

比较期间独占任务和模型操作，拒绝并发单点、按键切景、模型激活及其他启动。浏览器刷新不重发测试任务，并可恢复对比进度。清空只隐藏对比显示，原始记录保留。
