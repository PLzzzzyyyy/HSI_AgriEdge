# 2026-10-24 控制台评测与清空功能

最终候选：`gcs_eval_clear_20261024_v3`。
Release：`342273bc4a349cdda65a7ffea68cee4524f229f6c738ca84bf556b0f4dfbb055`。

## 使用

1. 刷新控制台，打开“评测指标”。在“评测任务”选择当前场景的历史板卡任务，即可计算 OA、AA、Kappa、宏平均 F1，查看每类精确率、召回率、F1、混淆矩阵和测试点覆盖数。
2. “评测当前结果”只读取已保存的板卡分类结果，不触发重新推理。“整景巡检并评测”会启动真实的整景任务；自动更新开启时，评测随已收到的分类结果更新。
3. 部分区域或未完成任务只代表已经覆盖的测试像素。全测试集覆盖率和任务范围内测试点覆盖率分别显示。没有测试像素时不生成精度数字；没有定义的类别指标显示横线。测试标签仅作对照，不输入板卡推理。
4. “导出 JSON”和“导出 CSV”保存本次评测的覆盖信息和逐类指标。CSV 为带 UTF-8 BOM 的中文表格。
5. “清空内容”移除当前分类显示、框选、探查卡、分析及评测显示；保留任务历史、原始分类数据、已保存地块以及板卡连接。清空本身不停止后台推理，需要停止时另按“停止”。通过“评测任务”或“历史对比”可重新打开历史。
6. 启动时不自动选择已结束的任务，也不会回放旧按键事件重新发起单点推理。单点任务仍使用真实 1×1 推理输入范围，但地图用探查点表示，不画成矩形选区。
7. 现有 START.bat / START_DEMO.bat 无需改命令：一键启动读取 `firmware/keys_20261018/deployment.json` 选择匹配的控制台与板端固件。

## 功耗计算口径（技术记录，不放入显示卡片）

- 功耗模型继续使用现有硬件对应的 Vivado 温度/功耗表，模型 ID `a4363b00`。固定活动率条件下，按芯片温度分段线性插值得到 PS+PL 芯片功耗；没有使用板载电流读数。
- 芯片温度来自 PS SYSMON；Cortex-A53 运行插值与积分；XTime 硬件计数器提供任务计时。沿用以太网传到 PC，同时由 PS 显示程序更新 DP。没有增加 PL 推理计算模块。
- 任务能耗为任务接受至完成/停止期间的 `sum(P * dt)`，包含准备和暂停。每像素能耗为 `1000 * E / 已完成像素数`。结束后冻结该任务记录。
- 温度过期后使用现有 40°C 模型点，并在机器数据保留有效状态与缺失时间；界面不再显示冗长来源说明。数据的 `measured=false`、模型来源及范围字段仍保留，不能将此数据解释成整板输入端电流实测功率。
- DP 和 PC 使用简短标题“芯片功耗”“本任务能耗”，计算逻辑与本次 UI 修改前相同。
