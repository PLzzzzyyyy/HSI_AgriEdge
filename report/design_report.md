## 摘要与报告范围

本作品面向无人机高光谱农情数据的边缘分类与地面分析，采用 ALINX AXU5EV-E 平台，将张量 Transformer 的主要编码与分类计算部署到可编程逻辑，在处理器侧完成输入准备、任务调度和外设交互，并通过 PC 地面站与 DP 终端展示分类、置信度和地块统计。参赛方向为 AMD 自主选题初级组，团队为光谱拾穗 / Gleaners。

稳定计算路径为 K7、W16A18、ABI4、TT_M3_OVERLAP=0：PS 准备 7×7×270 输入邻域并嵌入，PL 顺序执行十二层编码和分类头。投影内部采用三模积数据流、位置与通道并行、权重及中间结果片上复用。软件支持单点、区域、整景和多边形地块任务，并提供按键离线运行与联网移交。

## 1 选题背景、相关工作与创新点

### 1.1 应用问题

高光谱影像在每个像素上记录多个连续波段，能够辅助区分可见外观相近的作物。空间邻域又提供田块纹理与边界信息，适合联合光谱与空间建模。原始数据体积较大，完全上传后再处理会增加链路和等待开销。本作品以边缘端生成类别、置信度及区域统计为目标，将计算与任务执行放在板端，将交互、对比和农情核查放在地面站。

当前使用 WHU-Hi 无人机公开数据回放，不宣称已实飞或连接实时高光谱相机。低置信区域用于提示人工核查，不能直接等同于病虫害诊断；同一场景的不同权重也不能作为真实多时相长势监测证据。

### 1.2 相关工作与本项目定位

算法基于 Tensor Transformer for HSI Classification 的张量结构及公开实现，数据采用 WHU-Hi。项目继承了 Zynq-7020 前代投影加速经验，扩展到 UltraScale+ 的整网引擎和应用系统。算法结构与数据集属于已有工作，本作品的主要贡献在计算映射、数值契约、硬件存储调度和板端到地面站的工程实现。[S14,S15]

| --- | --- | --- |

### 1.3 工程创新的验证边界

三模积流水与并行阵列直接对应源码和综合结构，性能由板端计时证明；地块统计只累计实际收到或完成的像素，避免把未识别区域外推为已识别面积。当前没有完成面向所有公开硬件实现的同条件横向评测，也没有独立量化各优化的消融增益，因此不作通用最优或全行业领先的结论。


## 2 系统原理与总体功能框图

```text
PC 数据/模型 → SD/DDR → PS 输入准备 → AXI → PL 编码与分类 → DDR → PS 结果
PC 地面站 ←以太网→ PS 任务控制 → DP 显示；KEY5/KEY6 → PS 离线任务
```

图 1 系统数据与控制关系。SD / DDR 提供已导出的数据和模型；PS 为输入、驱动、任务状态与外设控制中心；PL 执行稳定整网计算。PC 地面站通过以太网交换命令、分类结果和状态；DP 画面由板端应用生成。

| --- | --- | --- |
| PC 数据 / 模型准备 | 场景预处理、训练或权重导出、文件与校验信息 | model/、data/ |
| PS 裸机应用 | 读取场景、取窗归一化和嵌入、cache 维护、下发推理 | src/ps/tt_net.cpp、system/m3a_roi.cpp |

早期架构文件还描述了前端进入 PL、int8 和跨 patch 重叠等扩展。当前交付以已验证的 PS 前端 + W16A18 串行整网路径为准，不能把计划中的 CUBE / M3b 或 P2 候选画成当前部署路径。[S06,S16,S17]


## 3 模型结构、数据与数值设计

### 3.1 张量 Transformer 与输入组织

采用 unoverlapping 变体，每个中心像素从场景取得 7×7×270 邻域，经归一化与嵌入后组成 N=6 的 token 块；网络共十二层。Q、K、V 与 M 投影采用 Tucker 三模积结构。注意力由分数矩阵、Softmax 与上下文加权组成，之后执行残差及 M 投影，末端分类头读取 token 1 的 2646 维特征。这里的 M 是代码中的张量投影，不直接套用常规 ViT 的两层 GELU MLP 示意。[S14,S16]

### 3.2 数据、模型版本与划分

| 场景 | 类别数 | 模型与固定划分 | PC 浮点 OA / AA / Kappa |
| --- | --- | --- | --- |
| LongKou | 9 | v2，自训 seed 0；Train100/Test100 | 0.9384 / 0.9273 / 0.9201 |
| HongHu | 22 | 各景独立训练、独立权重 | 0.8482 / 0.8485 / 0.8129 |
| HanChuan | 16 | 去末 4 波段，独立权重 | 0.8590 / 0.8328 / 0.8359 |

表中为历史 PC 评测，不是三个场景的板上全集精度。训练脚本为 model/train_scene.py，采用 Adam、初始学习率 1e-3、余弦调度、batch 128、最多 500 轮，以验证集选择模型；从 Train100 每类取 10 个作验证，测试集不用于选择权重。LongKou v2 checkpoint 前缀为 3f8acada1311，当前引擎权重 CRC32 为 27231983。多景分别训练不能证明跨景泛化。[S14]

### 3.3 定点契约与替代方案取舍

稳定路径为 W16A18：投影权重 16 位，片上激活 18 位 Q5.12。输入接口仍包含 int16 数据；各类中间量按相应头文件执行舍入、饱和和累加。注意力采用整数 scores、查表 Softmax 和整数上下文累加；token 统计中仍存在浮点平方根与除法，不能称为全网络只用纯整数。

原 Q3.12 激活存在超过 ±8 后的饱和，历史抽样中最大 logit 误差可达约 2.10。保持十二位小数并扩到 Q5.12 能降低饱和误差；把十六位改成 Q4.11 / Q5.10 会损失小数精度且出现标签翻转。int8 另有 PC 整数参考和 QAT 研究，未替代当前已部署 W16A18 路径。选择依据来自已有数值扫描，不能把 PC 精度视为 int8 硬件已通过。[S06,S14]


## 4 PL 数据通路与片上存储

```text
片上 X → mode1 → t1 乒乓 → mode2 → t2 乒乓 → mode3(K7×54) → 暂存写出
投影核依次复用 Q/K/V/M；层计数 0～11；权重与层间结果片上复用
```

图 2 三模积投影与缓冲结构。DATAFLOW 发生在不同 token 的 mode1、mode2、mode3 之间；框宽不表示真实耗时。稳定路径关闭后加的跨 patch / 投影注意力重叠候选，但保留投影内部的数据流。

### 4.1 K7 并行阵列

第三模积计算 Y[a,b,c] = Σ T2[a,b,j] × W3[c,j]。K7 固定一组 a 时，同时更新 7 个位置与 54 个输出通道，共 378 路逻辑乘加；j 从 0 到 53 推进。一个输入复用于 54 个输出，一个权重复用于 7 个位置。378 表示该级逻辑并行更新数，不等于整个设计 DSP 数，也不表示每拍生成 378 个最终输出。

结果先进入 pend 暂存，再按每拍 7 个值进行舍入、饱和与写回，可与下一组累加交叠。实际 HLS 报告中 mode3 主循环 II=1、循环次数 378，模块延迟 443 拍；包含三个计算级的数据流间隔为 444 拍。这是局部综合调度证据，不代替完整网络板测延迟。[S16]

### 4.2 存储与资源复用

xb、t1、t2 按访问维度分组，向并行计算单元提供同时读写能力；第三模积权重按输出通道打包存入 URAM。Q/K/V/M 分时复用同一组三模积核，十二层通过层计数器复用计算模块。Q 保存在 QB，K 使用后由 V 覆盖原 KB；普通 CLASS / LOGITS 路径的层间结果保留在片上。残差写回时同步累计和、平方和，减少为下一次归一化额外遍历。

注意力 scores / context 采用 6 token × 4 lane 的并行点积组织；Softmax 展开为减行最大值、两张指数查表、求和、串行倒数与乘法移位。分类头最多支持 24 类的并行累加。片上复用降低了外部层间交换，但输入和最终结果仍经 DDR，调试 DUMP 属于额外写回路径。


## 5 PS/PL 接口、协议与可靠执行

### 5.1 寄存器、数据与 cache

| 接口 | 设计内容 | 正确性要求 |
| --- | --- | --- |
| 控制 AXI4-Lite | PS HPM0_LPD → s_axi_CTRL；基址 0x80000000 | 读回 ABI / 位宽 / 小数位；源头为 tt_engine_regs.h |
| 数据 AXI | m_axi_FM 与 m_axi_WT 经 HP0 / HP1 访问 DDR | 非一致性端口，输入 clean、输出 flush/invalidate |
| 权重装载 | TTE2 权重包、版本及校验；LOAD_W 与 bank 选择 | 装载成功后方可计算；不同场景不混用权重 |
| FULL 输出 | CLASS、LOGITS、FEAT / DUMP 等模式 | 类别零基；CLASS 每像素 32 位 |
| CLASS 字段 | 低 8 位类别；高 16 位 Q0.16 置信度 | 中间 8 位为 0；1.0 饱和为 0xFFFF |

驱动计时与输入输出校验包含缓存维护和轮询，避免把仅算核内周期写成应用完整调用时间。错误返回、超时、模式不支持和权重身份不匹配都应使任务显式失败，不能继续显示旧数据为新结果。当前驱动以共享寄存器头和冻结 BSP 为准，重建时不能随意替换地址映射。[S01,S06,S18]

### 5.2 网络与任务身份

PC 与板端以 boot、session、task、release、场景与模型 CRC 等标识关联命令及回包。分类结果和状态分开管理，完整结果由接收去重、完成范围与校验信息确认；恢复连接不自动把旧任务当作新任务。地面站负责汇总已经接收的板端预测，不调用 PC 模型伪装为板端输出。

### 5.3 终端、按键与移交

KEY5 单击随机单点、双击整景；KEY6 单击矩形、双击简单多边形；长按两秒安全停止后切景，KEY7 保持硬件复位。采用 25 ms 消抖和 350 ms 多击窗口，区域任务同时限制实际面积与演示像素预算。无 PC 心跳时板端本地 Runtime 接管；任务结束并核对身份后显式移交 PC，迟到命令不能覆盖离线任务。[S08]

DP 顶栏显示实际指令状态：空闲 / 执行 PC / 执行终端；心跳不会覆盖执行状态。温度取 PS SYSMON。芯片参考功耗来自 Vivado 向量无关模型，40°C 参考 6.029 W、报告置信度 Low，任务参考能耗为估算功率积分；它们均非整板实时功率测量。[S06,S09]

## 7 同板性能对比与计时方法

### 7.1 固定测试条件

2026-10-26，在同一块 AXU5EV-E 的 Cortex-A53 #0 上，用 LongKou 零基行 51、列 358 的单像素输入。归一化 float32 CHW [270,7,7] patch 在两端复用同一板上内存。每条路径预热一次，再重复十次，取延迟算术均值；没有后台地面站通信和显示回调。[S01]

| 路径 | 均值 ms / 像素 | 相对 PL | 输出检查 |
| --- | --- | --- | --- |
| 配套 PS 基线 | 357.731842 | 98.479122 倍 | 类别相同；max |Δlogit|=0.002254963 |
| 当前 PL 方案 | 3.632565 | 1.000000 | PS embed + FULL LOGITS + 驱动维护 |
| 补充同算术 PS 整数参考 | 417.916257 | 115.047142 倍 | Q16 logits 逐项一致，误差 0 |

主结果采用原配套 PS 基线的 98.48 倍，不把补充整数参考的 115.05 倍混入主结论。倍率从未舍入均值相除，不能用显示的 357.732 和 3.633 重新得到不同口径的宣传数字。

### 7.2 计时边界

起点是已取窗、已归一化的输入 patch，包含 PS 嵌入、完整十二层编码与分类头，终点为 PS 获得 logits。PL 路径包含输入缓存维护、驱动寄存器调用、完成轮询、输出缓存维护和输出拷贝。取窗、归一化、首次权重加载、读盘、JTAG 下载 / 读取、网络、显示和日志在计时外。

PS 频率来自 BSP：1066656005 Hz；PL 配置读回约 199998000 Hz；计时器 33333000 ticks/s。它们是配置与驱动读回值，没有进行示波器频率测量。结果适用于本项目配套实现与选定输入，不代表通用 CPU、最优 CPU 实现或整景端到端加速比。

| 时序 | WNS +0.447 ns；WHS +0.005 ns | Vivado 2026.1，xczu5ev-sfvc784-2-i |

以上直接取自当前 KEY ECO 工程 utilization.rpt、timing.rpt 与 package.json，位流 SHA256 为 9c0c1732275e941811d110466a16c92d40fe833b1f93b4af27e8a4008b744ce1，与单像素测试部署硬件一致。不要用旧 10 月 7 日的 LUT 57060 / BRAM 113.5 或视频中的历史表替代当前值。[S01,S02]

### 8.2 P2 候选的同条件 HLS 对比

| P2 实验 | II | 估计 ns | LUT | FF | DSP |
| --- | --- | --- | --- | --- | --- |
| 原实验基线 | 9 | 18.407 | 155428 | 164050 | 417 |
| A：显式写口与仲裁 | 5 | 12.292 | 149067 | 118724 | 417 |
| B：CONTEXT 乘法流水 | 6 | 12.089 | 145913 | 113917 | 392 |

条件固定为 HLS 2026.1、XCZU5EV-2、5 ns、uncertainty 1.35 ns，三项均为 HLS 估计。候选 A 的 FF 下降约 28%、LUT 下降约 4%，II 从 9 降到 5；但两个候选 LUT 均高于器件 117120 容量，估计周期也未达到 5 ns。原 P2 实验基线不等于当前串行部署基线，不能将两张表当成同范围消融对比。[S05]

当前选择保留稳定 K7/W16A18 IP，并更新显示和应用功能。优化候选通过了各自范围的黄金回归与 CSim，但未完成最终资源、时序和板端性能验收，没有替换运行位流。两毫秒仍是优化目标；现有数据不支持宣称已实现两倍提速。


## 9 大模型协作、人工判断与失败分析

### 9.1 工作流与证据留存

协作采用“先定义契约与验收 → 读取来源与日志 → 小步生成或修改 → 保存失败 → 针对验证 → 人工判断取舍 → 冻结源与产物”的工作流。模型协助代码、构建脚本、参考验证和文档；人负责选题、板卡与材料确认、目标取舍及关键验收。这里描述的是开发协作流程，没有实现 3.1 智能体评测所需的独立读题、自动代码生成和题集评分服务。

### 9.2 真实协作案例：PS 平台配置

2026-09-23 的记录保存了用户提问：“这个是构建的什么平台完全copy7020的那个吗”。模型回答要点是：PS 配置来自厂商出厂工程，7020 的 ps7 配置不直接复用；PL 结构沿用投影核方案，但 IP 按 ZU5EV 重新导出。实际抽取 1013 项 PSU 配置，只覆盖既定外设 / 时钟项，并检查初始化代码和平台生成。[S10]

人工预先确定“板上数字只认实际输出，HLS 只看趋势，构建与板端验证分阶段”。当时默认器件跟出厂工程 xazu5ev -1，是历史构建选择；当前 KEY ECO 报告明确为 xczu5ev -2。新报告保留这一版本差异，不擅自把旧报告重命名为当前器件结果。

### 9.3 纠错轨迹与后续决定

| 失败 / 观察 | 纠正与验证 | 保留边界 |
| --- | --- | --- |
| 正则未覆盖 ps7_init 空白和变量表达式 | 调整解析规则，调用统计达到 756 次；与初始化序列比对 | 不把未解析项静默丢弃 [S10,S12] |
| XSCT 失败但退出码仍为 0 | 检查 CHECK PASS 及驱动头文件；错误头文件负例须失败 | 进程返回 0 不是平台通过证据 |
| HLS 相对路径读到旧候选源 | 固定工作目录、核对 CPP 路径与冻结哈希，撤回错误归因 | 原错误标记 invalid_source_binding [S05] |
| P2 候选资源和时序不满足 | 保留实验，不更新当前位流；记录失败和下一步瓶颈 | 仿真通过不等于部署通过 |

本节摘取已有日志的提问、回答要点和纠错，没有补造完整聊天、效率倍数或 pass@1/pass@5。原始协作文件随 S10 交付，可检查“任务—提示与回答—失败—人工判断—验证”的关联。

## 12 复现步骤：验证、重建与已知依赖

### 12.1 可重复的结果检查

单像素数据可完全离线复算：verify_submission.py 读取随附 1664 字节 board_result.bin，核对结构 magic / 版本 / 状态，按计时频率换算三条路径各十次 ticks，重算 98.479122 倍与 115.047142 倍，并检查整数参考 logits 和类别。samples.csv、results.json 与构建清单用于人工核对。此过程复算已有实测数据，不产生新板测。

### 12.2 HLS 与 Vivado 构建路线

历史稳定引擎使用 Vitis HLS / Vivado 2020.2；当前 PS 应用和按键 ECO 使用 2026.1。保留旧工具是为兼容既有 IP 和冻结结果，不能把 2020.2 产物称为全流程 2026.1 重建。按 GUIDE 允许使用其他版本但须说明的要求，本报告显式列出版本。

### 12.3 从零复现的实际限制

## 13 局限、后续工作与条款对照

### 13.1 当前结论与后续优先项
