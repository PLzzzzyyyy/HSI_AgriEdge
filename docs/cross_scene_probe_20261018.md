# 切景后单点探查不可用修复

问题复现：龙口的单点任务已完成，再手动切换到洪湖并选点。右侧仍显示旧任务完成、1/1，探查按钮却提示“正在等待当前任务信息”。实际板卡连接正常，洪湖模型已登记。

原因是网页全局 `S.live` 保留了龙口任务，但当前洪湖没有可绑定的任务。旧判断只有在 `S.live` 完全为空时才允许建立 1×1 任务，于是既不能探查旧任务，也不能为洪湖新建任务。切换模型也存在同类问题。

修复后按“场景、模型、实时选择状态”核对当前任务：

- 当前场景/模型没有实时任务，且原任务已结束时，选点后可显式新建本场景、本模型的 1×1 任务并读取完整 PL 探查。
- 原任务仍运行或暂停时，拒绝覆盖，提示先停止或等待。
- 相同场景/模型继续使用独立探查通道，不把探查结果计入原区域面积。
- 历史结果保留；显式查看其他模型的历史任务时不向其发送探查。
- HTTP 回执先于 WebSocket 到达时也能绑定新任务；晚到的旧模型更新不覆盖当前选择。
- 切景/切模型的等待页清除旧任务进度；按钮状态刷新不再覆盖温度遥测值。

离线检查：`tools/tests/test_cross_scene_probe.js` 执行实际 BoardPanel，覆盖切景、换模型、忙碌拒绝、旧任务保留、HTTP/WebSocket 顺序和相同任务独立探查；原单点后端、中文类别及按键切景回归通过。

实机检查：洪湖行 351、列 152，修复前直接后端验证和修复后真实板端任务均返回 `FE400003`（棉花，99.32%），22 个 logits 完全一致，432 个注意力原字的 CRC 均为 `6b4743ae`。实际前端处理代码在 DOM 测试环境中使用真实 HTTP/FPGA 结果完成绑定，22 类概率轴为中文；未进行桌面浏览器点击自动化。记录见 `.runtime-tmp/honghu_probe_before_ui_fix.json`、`.runtime-tmp/cross_scene_live_verification.json`，实际 DP 截图见 `.runtime-tmp/cross_scene_actual_dp.png`。
