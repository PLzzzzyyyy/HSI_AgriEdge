## 1. 结论：不为阶段名称再跑一次

原计划 [system_20261009_m3a_first_handoff.md](system_20261009_m3a_first_handoff.md) 的S1c出口是“小ROI用户Build/下载、回传结果，与对应参考核对取窗/embed/类别/置信度”。后续S1b轮已取得真板输出和同口径参考，不应因记录仍叫S1b而重新执行成功批次。

- **已有证据足以建议原15像素的输入口径及端到端CLASS功能有限验收**：真实SD→PS取窗/embed→冻结串行M3a→结果提交→UART，完整CLASS含类别/保留位/置信度15/15相同。
- **证据强度分开**：取窗/embed为实际源、编译对象与两路离线数值的交叉核查，不是板端中间张量直接读回。原计划未明确要求逐层/中间dump，也未把OA、性能、长稳作为S1c前置，不能擅自追加实验。
- **最小剩余缺口是验收边界确认**：由用户决定是否接受上述间接输入证据加最终CLASS逐字一致，作为进入S2的有限门禁。若要求板端patch/input/logits直接读回，则是尚未覆盖的更强验收，必须另报最小改动并获授权；本轮不默认要求、不生成dump、不重跑。
- 原UART的`NOT a board acceptance test`横幅保留。有限验收建议来自后续外部证据审查，不能修改横幅或把原App包装成自带完整验收套件。历史报告“非完整S1c”仍成立。

## 3. 一个最小下一步及所需授权

**推荐：确认有限S1c边界后，下一轮直接做S2a“空闲态PING/PONG/STATUS最小板端源码与定向编解码检查”**，不再整轮重复本评估。S2a是S2准备子轮，不是S2真板在线通过。

建议授权范围：
1. 确认第1节的有限验收可进入下一阶段，保留未覆盖项，不追加数值实验。
2. 只读核现有BSP/UDP参考；新增`src/ps/net/`最小v1模块及独立主机检查/报告。仅空闲状态PING/PONG/STATUS、来源地址回包和字段验证；STATUS未知指标先核协议表达，不伪造0或沿用旧性能值。不支持的业务命令不虚报成功。
3. 主机检查仅用于新代码语法/纯编解码/输入边界，**不是fake board、模拟网络验收或真板测量**。不运行UDP服务，不改`gcs/`，不接ROI任务/START/ROW/补传/权重下发。
4. 不修改旧driver/数值/公共接口、用户平台/App、冻结XSA或原包；不重建/重打包/下载。后续用户Build、真板回执、地面站v1适配另获授权。
5. 成功或出现必须扩大范围的阻碍即停、四件套。若希望连真板验证也做，需另明确允许独立App最小接入及用户Build/下载，当前无此授权。

**提前暴露的S3风险，不是S1c失败**：`src/ps/tt_m3a.cpp::execute`在FULL/LOAD_W期间同步轮询；`src/ps/system/m3a_roi.cpp::tt_m3a_roi_run`连续跑完ROI。protocol §3.1要求等待引擎时仍服务网络。直接拼接不能证明运行时心跳/命令及时性。S2a空闲链路可隔离完成；S3前须针对有界调度/等待期服务能力报告最小接口改动并另获授权，不能偷偷改旧driver或靠多核/双缓冲绕过。失败后只能用CPU已提交前缀/状态，不得读取仍可能DMA的output。

## 4. 距离闭环还有几步

计数单位是**验收关口，不是固定聊天轮数或工期**。另有本次1项“有限S1c边界确认”，不算新实验。

### 最小可演示系统：还需3个集成关口

| 关口 | 最小结果 | 边界 |
|---|---|---|
| S2 真板在线 | 板端最小链路、地面站v1结构/在线接入，真板PING/PONG/STATUS回执 | BSP有lwIP和S2a主机检查不等于S2通过 |
| S3 单ROI地面站闭环 | 用户发任务→板端计算→ROW/完成状态→地面站显示；板端完成且收齐才判完成，计数/坐标/结果一致 | 历史UART回放不算新UDP集成，PC推理不能补板源结果；新集成运行另授权 |
| S4 DP本地监视闭环 | 同一板端结果接DP，共用语义/调色板；断网后已启动任务仍计算、DP仍更新 | 需有足够未完成工作并另批最小范围；15点结束后拔线不证明继续计算，恢复补齐留S5b |

可适度合并**同一关口内**代码、针对性检查和已授权人工回执核查，减少纯流程拆轮；不能跨关口自动推进，不承诺固定轮数/天数。

### 原计划完整业务与交付：上述3关之外再8关，合计11关

- S5a：切景、框选、整景真实通路，按场景/数值口径验收。
- S5b：断线恢复、缺行补传、真实链路指标；含原计划拔线30秒再接回完整性，C3/S4不能替代。
- S5c：串行M3a权重版本/校验/安全切换与失败保留；不套INT8包、不默认双权重库。
- S5d：板源评测/探查、固定测试划分与准确率证据，不回退PC。
- S5e：真板农情分析→人工核查→PC训练或明确标注的预训练版本更新→下发→板端重跑比较。此时才覆盖PLAN §15业务闭环，不是仅两屏出图。
- S6a：分项/端到端时间与持续性；S6b：实测功耗、链路/画面指标；S6c：复现、录屏、报告、技能/许可及交付清单。仪表与具体验收逐项确认，发布/push另授权。

P2/2ms不计当前闭环前置，仍暂停；G2/旧OOC FAIL保留。SYSMON暂缓，不因温度栏自动恢复诊断。不承诺“再三步就完成所有比赛交付”。

## 5. DP与地面站：同源结果，不同职责（建议，未实现）

| 维度 | DP：板端独立监视，回答“板子是否在算” | 地面站：任务/农情工作台，回答“结果意味着什么、下一步做什么” |
|---|---|---|
| 主画面 | 分类缩略图/当前ROI、已提交计算进度、已完成/总像素、运行/完成/安全停机 | 大地图底图叠加分类/置信度、框选/任务控制、图层切换 |
| 诊断 | 景/任务标识、权重版本或校验标识、最后错误/完成前缀、链路状态 | 接收进度/缺行、命令ACK、链路/恢复状态、日志 |
| 分析 | 只显示不交互；语义映射核实前可只显示数字类别 | 地块/像素统计、低置信待核查斑块、补采样、人工标注/模型对比与更新 |
| 断网 | 从本地CPU已提交结果绘制，继续计算/更新，不依赖网络帧 | 显示离线/最后接收时刻及缺口；失联不等于停止/完成；恢复补齐待S5b |
| 测量 | 新系统实测前时间显示“未测”；温度/功耗无可靠来源则“未测/暂缓” | 同样只报有来源实测；PC/历史回放显著标注，不顶替板源 |

最小布局：DP左分类缩略图、右状态/计数/版本、底部进度/错误；地面站保留大地图、控制栏和农情页。本轮不画原型/改页面/添依赖，沿用单核裸机、单1080p帧缓冲方向，内存/cache/刷新预算在S4核验。

两端共享任务身份、ROI坐标、类别映射/调色板、置信度`raw/65536`；未完成像素用独立视觉状态，不能把类别0当未计算/背景。DP显示**已计算**计数，地面站显示**已接收**计数，断网时不同是正常的，在线收齐后核一致。两端消费成功提交结果，不从超时DMA缓冲绘图/发包。

无地理标定时只报行列/像素/占比，面积需有效地面分辨率；低置信只称“待核查”，不是病害诊断。真值仅用于评测，不作业务输入。15点只能明确标注为历史已验收ROI示例，不能渲染为整景农情结论。
