## 1. 目标与不变边界

- 默认目标：**优先提高多patch计算吞吐，兼顾单patch延迟、精度和资源**。持续整景吞吐另计，不能用重复A的窗口内服务率代替。若用户后续改为单点最低响应延迟，调整优先级，不默默把吞吐收益写成延迟收益。
- 串行对照冻结：含PS embed单patchLOGITS **3.628719ms**；n16含PS embed CLASS **3.626181ms/patch，275.772patch/s**；预embed n16 CLASS **3.394514ms/patch**。证据 `board/m3/20261007_acceptance/`。
- 原XSA `build/vivado/tt_m3a_zu5ev.xsa` SHA256 `9813b5632250839274e6e298e5e4df8ea601b6d41016351148f98cf6057d9652`。原 `vitis/m3a_plat` / `test_m3a`、导入包及ELF保持不动，候选独立命名/目录，不覆盖旧输出。
- 用户负责Vitis Build/下载。M1/M2/C3已过项不重测，SYSMON暂缓，不新增电源管理任务。INT8训练沿用现有过PC精度门槛的QAT权重，不默认重训或改变数值契约。
- 现有 `TT_M3_OVERLAP` 默认0不改；停止的v2只有完整CSim通过，无综合/RTL/时序结果，**不自动恢复旧任务，不靠旧.done/exit0判成功**。

## 2. 总体路线：先建立成本模型，再用 INT8 支撑有效流水

```text
S0 阶段耗时/依赖/存储端口预算（必做，先不重跑硬件）
        ↓ 收益筛选：只留最有希望的组合
S1 位宽可配置的流水调度模型 + INT8算术/打包小核验证
        ↓ 决定先流水还是先压位宽，不做两套不可复用架构
S2 集成多patch分阶段流水 + 必要的片上布局/搬运优化
        ↓ 只对关键瓶颈增加INT8 lane/并行度，重新平衡阶段
S3 按新瓶颈决定是否做PS双缓冲、输入通路或M3b前端
        ↓
S4 候选同口径对照 → 完整RTL → 系统时序/资源 → 用户上板
```

主攻**单套共享权重/投影核 + 多个patch上下文 + 不同阶段并发**，不是复制两套整网；INT8是可能释放运算/缓冲预算的手段。调度从P=2验证，P=3仅在阶段等待无法隐藏且存储端口可满足时尝试。`P`是片上在飞上下文数，`n_patch`是一次命令处理总数，**n=16不代表有16路硬件或16个片上上下文**。

### 筛选原则（工作量门槛，不是预测/验收承诺）

- 先比较每项的可隐藏/可删除时间、额外buffer/端口、数值风险和验证代价；最高收益组合由S0结果决定，不能现在断言一定是INT8或P=3。
- 默认把**计算吞吐至少20%改善潜力**作为高投入路线进入整网实现的筛选目标；5%以内且不能为后续释放关键资源的改动先搁置。5%～20%的低风险改动可作为主线前置或顺带合并，避免为它单独重建用户平台。
- INT8即使单独不提速，只要明显解除关键DSP/存储约束、使流水成为可能，也可继续；否则不因“8位”标签强行采用。
- 筛选是条件判断，不设“必达2倍”“必到1ms”；采用候选必须有实际同口径收益或明确的资源换吞吐价值。最终未有胜者时保留串行基线，报告失败原因而不是降低数值/时序要求。

## 3. S0：下一轮最先交付的收益账本

### 任务
1. 只读复用已有HLS报告、完整串行RTL事务、源循环和系统资源，区分load、stats/norm、Q/K/V/M投影、copy、scores/softmax、CTX/残差、head、最终store。每一项标**实测/仿真/估计/未知**。
2. 形成每patch与每层的依赖图；Q→K就绪后才能scores，V与attention都完成才能CTX，残差/归一化完成才能同patch的MLP/下一层。Q/K/V/M共用投影单元，其服务次数必须累加；norm和共享RAM端口同样单列，不能画成无限资源流水。
3. 建立小型事件调度模型，扫P=1/2/3、INT16/INT8、共享/独立缓冲方案。模型包含回流依赖、有限buffer、每端口每拍吞吐、队列等待及启动/排空；输出单次latency、稳态II、实际有限批总时间、各单元占用率。
4. 存储账本按X/XN/Q/K/V/ob/stats/attn/权重逐项列：位宽、存活区间、每拍读写、分bank/复制/PIPO、物理BRAM/URAM粒度与端口。当前系统BRAM113.5/144、DSP620/1248、URAM20/64、WNS+0.067ns。不能把逻辑字节减半直接当BRAM减半，也不能把一个双口URAM当任意多bank替代品。
5. 评估片上copy_ob和重复扫描的可移除部分，以及直接输出下游布局是否改变投影倒出II；避免节省copy却拖慢主核。现有“V/attention约0.206ms、copy约0.477ms”仅旧HLS量级，不能无重叠地相加当收益。

### 完成门槛
- P=1成本模型与原串行RTL差异逐项解释；不能解释的大差异先标未知，不使用不可信模型给毫秒目标。既有HLS估计与RTL有差，不能拿旧估计直接填满账本。
- 若缺关键分段信息，先给出缺口和最小获取办法（如候选诊断RTL/仿真事件），收益理由成立后再运行；本轮不要求用户重复串行板测，也不修改生产接口只为打印profile。
- 输出一个优先组合、一个回退组合及不做项。**没过S0，不直接写整网INT8流水、不直接启动一批Vivado。**

## 4. S1：INT8与多上下文设计的低成本可行性验证

### INT8：先小核，后整网
- 复用 `model/engine_ref.py --num 8`、`sim/golden/n6_engine_i8/` 和已导QAT权重。当前HLS仅W16/A18，文档`TT_NUM=8`不是已实现开关；候选需要位宽/小数位/权重指数/舍入与饱和的完整实现，不能只换typedef。
- 先验证mode1/2/3中最能影响主瓶颈的小核：共享一个操作数的DSP双乘打包、符号修正、16项分段累加（mode3 54项为16+16+16+6）、指数表移位；累加与softmax保留所需宽度，分类头按既有契约仍用16位权重。
- 针对极值、正负混合、段尾、不同指数、舍入边界和饱和构造逐位测试；再用三景真实权重/输入片段与INT8整数参考逐位核对。不拿“标签相同”替代打包算术精确。
- 只有小核验证通过，才做**有限的**候选HLS综合/必要的OOC映射检查：确认真实DSP映射和每拍吞吐，而不是凭源码打包式或HLS DSP估计认定双乘成立。OOC资源只筛选，最终决策看系统实现。
- 比较两个用途：同lane少资源 vs 同预算更多lane；把段间加法、移位、memory端口及潜在频率降低全部计入。少DSP但II更大、资源释放又不能被流水利用时，不推进整网INT8。

### 多patch流水：先确认调度与所有权
- 设计位宽可配置、P=1可退回顺序执行的调度；先P=2，分别维护每个patch的层号、阶段状态、输入/输出地址及有效性。权重共享，不为每patch复制整套权重。
- 典型重叠是“投影核处理B时，attention/残差处理A”，不是强行让同patch相互依赖步骤并行。将共享投影、归一化和端口都纳入调度冲突检查。
- 设定buffer的唯一写者/读者完成条件，未完成读取消费不得覆盖旧K/V或复用上下文；结果按原patch顺序提交。计入队列满、等待、尾批和排空。
- 位宽选择由S0预算决定：**若INT16 P=2已可行且预计收益明显，先跑共享架构的INT16验证；若BRAM/端口受限，先完成INT8存储/算术，再启用同一调度。** 不先铺一个高成本INT16整网流水后推翻重写。

## 5. S2：主收益集成与消融

只集成S1胜出的设计，至少保留逻辑上可分离的对照；下列是配置标签，不是声明现有宏已支持：

| 配置 | 位宽 | 片上上下文 | 用途 |
|---|---|---:|---|
| B0 | 已验收W16/A18 | 1 | 冻结硬件/板测基线，无需重建 |
| B1（可行时） | W16/A18 | 2，必要才3 | 测调度/布局净收益；资源不容纳则记不可行，不强造板测 |
| B2 | INT8原契约 | 1 | 区分位宽/算术资源变化，不夹带多patch收益 |
| B3 | INT8原契约 | 2，必要才3 | 主候选：窄位宽+跨patch阶段重叠 |

- 片上copy/布局优化单独开关或独立提交；若B1/B2/B3同时依赖它，另在低成本模型/仿真中给开关对照。**不用为了凑全矩阵把每种组合都导成XSA上板**；只筛选胜者，缺失硬件对照如实注明，不声称精确分解了每项板上收益。
- 核心数值：INT16候选对INT16整数参考逐位；INT8候选对INT8整数参考逐位。INT8 vs INT16以官方Test OA/精度预算比较，不要求logits逐位一致。已有三景OA门槛是下降≤0.5个百分点，前提是实现严格服从原整数契约；改契约或参考路径就需重新评估全集。
- 流水测试至少涵盖n=1、2、3、P−1/P/P+1（合法值）、16、非整倍尾批、连续多批不同输入、A/B/A、重复/重装权重边界、CLASS奇数尾、输出顺序、buffer guard与满队列。12层DUMP/续算可走明确的串行诊断路径，不计为流水性能；不能静默产生错误布局。
- 优先沿用现FULL批接口和输出顺序，减少PS变更。现INT8契约的M3a外部输入仍int16 Q3.12，装载时量化，**INT8不会自动把31808B输入跨度减半**。配套PS驱动需识别/严格核对INT8包及返回格式，不放松成“任意位宽都接收”。原tt_m3a保持独立。

## 6. S3：减少交互的正确顺序

1. **层间DDR/PS逐层调用**：已消除，保持；权重继续首次加载后驻片上；正式性能不DUMP，不每patch reload。
2. **片上buffer拷贝/重复扫描**：在S0～S2优先处理，属于主要计算通路优化；区分片上移动和AXI往返。
3. **PS与PL输入准备重叠**：PL加速后重新计算embed/准备占比。必要时独立候选驱动采用双缓冲，让PS准备下一批时PL处理本批，最多按明确定义的在飞事务管理；cache clean、输出invalidate、超时后不复用DMA缓冲都保留。先不省略cache维护来制造假加速。
4. **M3b取窗/归一化/embed进PL、行缓冲重用**：作为面向整景的条件后续，不与B3首轮整网集成绑定。先给相邻像素取窗/归一化/I-O的真实耗时与字节模型，再决定是否本轮做。协议已有CUBE位不等于当前硬件支持。
5. **输入/输出/控制仍必要**：输出CLASS适用于类别业务，LOGITS保留探查；批提交减少MMIO但当前收益很小。默认不做“零交互”、扩大总线/升频/权重双库等未证实需要的改动。

## 7. 筛选、实现与板测关卡

- G0：S0账本/资源/依赖检查完成，说明为什么选该组合，以及未知量是否影响结论。
- G1：INT8小核算术与调度模型测试通过；窄位宽确实释放限制资源或提高关键阶段速率。未通过则退回INT16可行流水/片上布局路线。
- G2：候选完整主机/CSim数值和所有权检查通过；HLS只作为筛选，查看DATAFLOW隐藏buffer、核复制、端口争用和II。冻结源/黄金/参数快照，拒绝覆写旧构建。
- G3：胜出候选完整12层RTL cosim通过；检查稳态间隔、有限批总时间、填充/排空、数值、输出顺序、deadlock/背压。对串行RTL同事务比较，计时计数器溢出/超时边界明确；不只测一层或只看Csim。
- G4：系统实现验证资源合法、200MHz目标时序满足、bitstream/XSA可追溯。实际频率下降时必须重算真实时间/吞吐，不能只比较拍数。OOC不代替系统时序；既有+0.067ns不构成候选的裕量承诺。
- G5：只把胜者整理独立源码包/XSA给用户Build/下载，保留串行回退。原基线日志直接复用，不无故要求重测；候选按相同输入/编译有效选项/输出种类/计时边界比较。长稳、整景及I/O需要独立结果，不由微基准外推。
- 普通“继续下一轮”从S0开始，不自动恢复停掉的overlap_v2。若证据表明任何主线不满足收益/资源条件，在关卡停下并给原因/备选；不要为完成计划而硬上板或改精度门槛。

## 8. 计时与收益报告必须分开

| 指标 | 统一范围 |
|---|---|
| 单patch latency | n=1；预embed与含PS embed分别列，包含driver/cache/MMIO |
| 批吞吐 | n=16为旧基线对照；可额外n=32/64检查平台期，报告批总时间、摊销与fill/drain；不是每patch响应延迟 |
| 持续双缓冲服务率 | 总墙钟从首批输入准备到最后结果可读，覆盖准备/等待/排空；检查/打印可在窗外，但必须说明；不得只加总互相重叠的子窗口 |
| 整景端到端 | 另含取窗、归一化、数据读写/输出；入口/终点及缓存状态固定，不能与现3.629ms口径混称 |
| 精度/资源 | INT8整数参考逐位+官方OA；LUT/FF/DSP/BRAM/URAM/系统时序，另列是否新增PL buffer及PS内存 |

加速不是“INT8×流水×搬运优化”的倍数直接相乘。每步都可能转移瓶颈；组合收益以统一时间窗实际结果为准。先warmup，记录raw ticks、重复次数、输入序列、实际编译命令、XSA/源/权重哈希。性能采用同一固定A便于复用旧数据；跨patch正确性必须使用多种不同输入，不能用全相同A掩盖顺序/串扰错误。
