# 地面站使用教程与说明

写给自己看的：怎么启动、每个按钮干什么、演示按什么顺序点、屏幕上的数字怎么理解、每个功能背后用了什么方法和理论、哪些已经验证过、哪些还没做。最后更新 2026-09-24。

---

## 1. 它是什么

浏览器里的地面站，连一个"数据源"，拿回逐像素的分类结果（类别 + 置信度），然后在 PC 上做面积统计、待核查斑块、地块台账、精度指标、前后对比和闭环更新。

数据源有两种，界面在其他地方完全一样：

| 数据源 | 谁在算 | 用途 |
|---|---|---|
| PC 推理 | 本机 GPU（RTX 4050）跑浮点模型 | 没有板子时演示，也是板上结果的比对参考 |
| 板卡 UDP | AXU5EV-E 板子；没板子时用 `gcs/fake_board.py` 模拟 | 正式演示；模拟板用来在没有板子时测链路 |

**红线**：PC 源和模拟板给出的速度、功耗都是本机的数字，**不是板上数字**，不能写进报告当板上结果。

## 2. 启动与关闭

```powershell
# 地面站服务（约 4 s 起来，会自动打开浏览器；加 --no-browser 则不打开）
D:\pytorch\python.exe gcs/server.py --port 8765
# 浏览器打开 http://127.0.0.1:8765

# 没有板子但想测板卡链路：另开一个窗口运行模拟板
D:\pytorch\python.exe gcs/fake_board.py
```

- 关闭服务：关掉它的窗口，或者 `Stop-Process -Id <PID>`（用 `Get-NetTCPConnection -LocalPort 8765` 查 PID）。
- 页面刷新后，历史任务会从服务端恢复；**服务重启后历史任务就没了**（结果只存在内存里，最多保留最近 16 次，更早的会从历史表里自动消失）。
- 顶栏数据源显示“服务断开，重连中…”，说明服务停了，页面会每 1.5 s 自动重连。

## 3. 界面分区

```
┌──────────── 顶栏：标题 │ 景 │ 权重 │ 二维地图/三维立方体 │ 数据源 ● │ 时钟 ────────────┐
│左│                                              │ 右栏                         │
│侧│           地图 / 三维立方体                    │  · 任务（类型、开始/暂停/停止）│
│工│   （浮动：左上图层、右上类别图例）               │  · 遥测                      │
│具│                                              │  · 种植结构                   │
│栏│                                              │  · 飞行任务                   │
├──┴─── 底部页签：单点探查│农情分析│地块台账│精度指标│闭环更新│链路与下发│历史对比│日志 ───┤
```

**记住一条**：左侧工具栏只管“在地图上怎么操作”（看、画），右栏“任务”卡片管“要算哪些像素”，顶栏管“用哪景、哪个权重、看二维还是三维”。

### 3.1 顶栏

| 控件 | 作用 |
|---|---|
| 景 | longkou / honghu / hanchuan。切换会重新加载底图，并清掉框选、地块和当前显示 |
| 权重 | **下一次任务**用哪个权重版本 |
| 二维地图 / 三维立方体 | 切换主视图，快捷键 C |
| 数据源胶囊（圆点 + 文字） | 显示当前数据源和链路状态。**点它会跳到“链路与下发”页签**，在那里切换数据源 |
| 时钟 | 本机时间 |

圆点颜色：蓝 = 本机（PC 源），绿 = 在线（板卡 2 s 内有包），红 = 断开。

### 3.2 左侧工具栏（地图操作）

| 按钮 | 快捷键 | 作用 |
|---|---|---|
| 平移探查 | V | 拖动平移地图；**单击像素**做单点探查（结果在“单点探查”页签） |
| 框选区域 | B | 在地图上拖出矩形，右栏任务会自动切到“区域识别” |
| 绘制地块 | P | 逐点单击画多边形，**双击结束**，Esc 取消正在画的；结果进“地块台账” |
| 适应窗口 | F | 把地图缩放到能看到整幅图。**只改视图，不做计算** |
| 跟随 | — | 整景巡检时让地图跟着推扫线走 |

滚轮缩放；右键或中键拖动也能平移（任何工具下都可以）。

### 3.3 右栏

**任务卡片**

| 控件 | 作用 |
|---|---|
| 标题栏右侧的“全速 / 30 / 10 / 3 行/s” | 回放限速，**只影响显示节奏**，吞吐按纯计算时间统计。演示时用 10 行/s 看推扫效果 |
| 整景巡检 | 从上到下逐行算整幅图（LongKou 22 万像素） |
| 区域识别 | 只算框选的矩形。还没框选时点它，会自动切到框选工具 |
| 评测 | 只算官方 Test100 测试像素，开始时自动切到“精度指标”页签，指标随进度实时刷新 |
| 区域说明 + **清除框选** | 显示当前范围；有框选时出现“清除框选”，点了去掉矩形并切回整景巡检 |
| ▶ 开始 / ❚❚ 暂停 / ■ 停止 | 暂停对 PC 源和板卡源都有效。板卡源下，暂停要等当前这批像素算完才生效 |
| **清空结果** | 地图上不再显示识别结果（种植结构、待核查斑块也清空）。历史任务还在，“历史对比”里重新选 A 就能恢复 |

**遥测卡片**：见第 5 节“数字怎么读”。

**种植结构卡片**：当前显示的结果里各类面积和占比，鼠标停在某一行上可以看像素数和平均置信度。

**飞行任务卡片**：数据集官方说明里的采集信息（地点、日期、平台、传感器、航高、GSD、影像尺寸、覆盖面积）。

### 3.4 地图上的浮动面板

- **图层**：假彩色底图、分类结果、置信度热力、真值（仅评测）、误分像素、斑块/采样/标注标记、地块；下面的滑块调透明度。
- **类别图例**：点某一类可以隐藏或显示这一类。
- 窗口宽度 ≤ 1200 px 时这两个面板默认折叠，点标题展开。

### 3.5 三维立方体视图

- 顶面 = 假彩色 + 分类叠加；四个侧面 = 边缘像素的全部波段（270 个）。
- **拖动**旋转，**滚轮**缩放，**单击顶面**做单点探查，“自转”自动旋转，“复位”回到初始角度。
- **剥离到波段**滑块：顶面换成某一个波段的灰度图，立方体高度随之变矮，像把立方体一层层剥开。
- 下拉框 **立方体：整景 / 立方体：框选区**：立方体显示整幅图还是框选的那块。只影响显示，不影响计算。

## 4. 常用流程

### 4.1 演示开场：整景巡检

1. 顶栏选 `longkou`、权重 `v2`。
2. 右栏选“整景巡检”，任务标题栏的限速选 `10 行/s`，左侧点“跟随”。
3. ▶ 开始。地图逐行出现分类结果，遥测卡片实时更新。
4. 结束后会自动做一次农情分析（见 4.4）。

不限速时，GPU 空闲情况下整景约 2 分钟（09-24 实测 119 s 纯计算）。

### 4.2 区域识别

1. 左侧“框选区域”（或按 B），在地图上拖一个矩形。右栏自动切到“区域识别”，并显示区域的行列范围和面积。
2. ▶ 开始。
3. 不要这个框了：点区域说明旁边的“清除框选”。不要地图上的结果了：点“清空结果”。

### 4.3 单点探查

左侧“平移探查”（或按 V），单击任意像素。“单点探查”页签显示：7×7 输入窗、邻域分类、光谱曲线、各类概率、12 层注意力矩阵（滑块切层）。在三维视图里单击顶面也可以。

探查用的是**地图上正在显示的那次结果的权重**（历史对比里的 A），所以探查给出的类别和地图颜色一致；地图上没有结果时才用顶栏选的权重。用的是哪个权重，写在探查信息的“权重”一栏。

### 4.4 农情分析（“农情分析”页签，三列）

- **待核查斑块**（左）：置信度低于阈值的连通块，加上周围全是别的类的孤立小块。点表格里某一行，地图会飞到那里并高亮。
- **置信阈值**调高时，更多像素算作低置信，但相邻的低置信块会连成一片，所以斑块**个数不一定变多**，低置信的**总面积**一定变大。
- **补采样建议**（中）：平均置信度最低的 15×15 窗口，最多 5 个、互不重叠，给地面人员去核查（区域太小时会少于 5 个）。
- **作物面积**（右）：面积 = 像素数 × GSD²。
- **导出报告**：下载一个 JSON（全部内容，含地块表）和一个 CSV（作物面积表）。

低置信和碎斑只表示“需要去地里看一眼”，**不是病害诊断**。

### 4.5 地块台账

左侧“绘制地块”（或按 P），依次单击多边形的顶点，双击结束。自动跳到“地块台账”页签，显示面积、已识别比例、主栽作物、主栽占比、混杂比例、低置信占比。地块名可以直接点击修改。地块边界是人画的，不是用真值图。

**地块台账自己不做识别**，它读取地图上当前显示的那次结果（历史对比里的 A），统计多边形里的像素。所以要先用整景巡检，或框选一个包住地块的矩形做区域识别。“已识别”不到 100%，说明那次识别没覆盖全，要再框选识别一次。先画后识别也可以：停在台账页签时，识别过程中表格会实时刷新。

清除地块：每行最右边“删除”，或页签上方“清空地块”；画到一半按 Esc 取消。

### 4.6 精度指标

两种用法：
- 右栏选“评测”跑官方测试集（LongKou 约 20 万像素）。开始后自动切到“精度指标”页签，**每 1.5 s 按已算完的测试像素刷新一次** OA / AA / Kappa、每类精度和混淆矩阵，说明行会写“运行中，实时刷新”。
- 对任何一次任务，点“计算当前任务指标”，只统计这次任务覆盖到的测试像素。整景巡检过程中停在这个页签，也会实时刷新。

**评测和整景巡检的区别**：整景巡检算整幅图所有像素，出完整分类图，用于面积、斑块、地块，是“实际应用”；评测只算有真值的官方测试像素，出稀疏的点状图和精度指标，是“证明精度”。整景巡检跑完后点“计算当前任务指标”，统计的也是其中的测试像素，同一模型下结果应与评测相同（按道理推断，未实测比对）。评测跳过了无标签像素和训练像素，所以更快也更干净。演示用整景巡检，报告里的精度数字用评测。

真值只用于评测，不参与识别。

### 4.7 历史对比

表格里选 A（显示在地图上），再选 B，就会出现左右滑动对比条，拖动中线对比；勾选“只看变化像素”可以高亮两次结果不同的地方。下方文字给出公共像素、变化像素，以及在有真值的像素上 A、B 各自的精度。B 选“无”则关闭对比。

### 4.8 闭环更新（只有 LongKou）

演示“旧模型不认识新作物 → 人工核查标注 → 更新模型 → 下发 → 复测”。设定：旧模型（hold3）训练时去掉了芝麻（Sesame），核查区 64×64，起点 (120, 20)。

| 步骤 | 按钮 | 发生什么 |
|---|---|---|
| 1 旧模型巡检 | 运行 | 用 hold3 识别核查区，芝麻大面积误分 |
| 2 地面分析 | 分析 | 出待核查斑块 |
| 3 人工核查标注 | 显示标注点 | 地图上显示 30 个标注点（取自官方 Train100，不碰 Test） |
| 4 模型更新 | **用已验证 v3** 或 **现场微调** | 见下 |
| 5 权重下发 | 下发 | 带 CRC32 分块下发；PC 源下就是本地切换模型 |
| 6 复测对比 | 复测 | 新权重重跑同一区域，自动打开历史对比，左 = 更新后，右 = 更新前 |

第 4 步两个按钮的区别：
- **用已验证 v3**：直接用事先训练并验证过的 v3，秒完成。演示时要说明这是“版本更新演示”。
- **现场微调**：真的在 PC 上训练 30 轮。**GPU 空闲时约 2.5 分钟**（离线实测 149 s；09-25 现场实测 146～147 s，其中训练 30 轮约 27 s，其余约 2 分钟是训练后对官方 Test 全集的评测）；如果 GPU 同时在跑别的训练，会慢十几倍，见第 9 节。完成后生成新版本 `liveMMDD_HHMMSS`，出现在权重下拉框里。

09-24 实测（用已验证的 v3）：核查区精度 27.66% → 69.73%，变化 2021 像素，和离线报告 `data/closed_loop/longkou/finetune_30.json` 完全一致。

### 4.9 链路与下发

**切换数据源**：选“PC 推理”或“板卡 UDP”，板卡要填 IP，点“应用”。
- 真板：默认 `192.168.1.10`。地面站在本机 UDP 5011 端口收，发往板子的 5010 端口。
- 模拟板：先运行 `gcs/fake_board.py`，IP 填 `127.0.0.1`。数据源显示“板卡 UDP（模拟板）”，遥测里的设备名带“（模拟）”。

**权重下发**：选一个版本点“下发”。板卡源下每块等 ACK，超时重发 3 次，最后校验整包 CRC32，显示“CRC32 校验通过”。**下发成功后，顶栏“权重”会自动切到这个版本**（等于“这个版本生效了”），并弹出提示。

**链路面板**：收发包数和字节数、丢包数（按序号缺口统计）；右边的柱状图对比“原始立方体 / 分类结果 / 权重包”的字节量。

## 5. 数字怎么读

| 显示 | 含义 | 注意 |
|---|---|---|
| 像素 / 秒（计算） | 已处理像素 ÷ 纯计算时间 | 不含显示限速和网络 |
| ms / 像素 | PC 源：GPU 计算时间；板卡源：板子 STATUS 包报上来的 PL 计时 | 模拟板报的是本机 GPU 时间 |
| 功耗 W / 温度 | PC 源：`nvidia-smi` 整张显卡；板卡源：板子上报 | PC 功耗包含显卡上其他任务 |
| mJ / 像素 | 功耗 × 计算时间 ÷ 像素 | 同上 |
| 结果量 4 B/px | 每像素回传 4 字节（类别 + 置信度 Q0.16） | — |
| 置信度 | softmax 最大值 | **是模型分数，不等于正确概率** |
| 面积 m² / 亩 | 像素数 × GSD²，1 亩 = 666.67 m² | GSD 取数据集官方说明 |
| 链路压缩比 135 : 1 | 原始立方体 270 波段 × 2 字节 : 分类结果 4 字节 | 只是分类结果对原始立方体。不能当整系统压缩倍率宣称（协议头、重传、底图都没算） |
| OA / AA / Kappa | 见 7.8 | 只在有真值的测试像素上算 |

## 6. 为什么有些按钮看起来重复

| 看起来重复的 | 实际区别 | 处理 |
|---|---|---|
| 左“适应窗口” vs 右“整景巡检” vs 三维“立方体：整景” | 缩放视图 / 启动整景计算 / 立方体显示范围 | 09-24 已改名消歧（原来都叫“全景”或“整景”） |
| 左“框选区域” ⇄ 右“区域识别” | 一个是画框的工具，一个是任务类型，两者**联动**：画完框自动切成区域识别；选区域识别但还没框，自动切成框选工具 | 保留。这是 GIS 软件常见的“工具 + 任务”布局 |
| 任务类型“评测” vs 页签“精度指标” | 前者跑测试集，后者显示和计算指标 | 09-24 页签由“评测”改名为“精度指标” |
| 顶栏“权重” vs 链路“下发” vs 闭环“下发” | 顶栏选下一次任务用哪个版本；下发把权重送到板子，成功后顶栏自动切过去 | 保留。闭环复测用的是闭环自己的版本，不受顶栏影响 |
| 顶栏数据源 vs 链路页签的数据源 | 顶栏只显示；设置在页签里 | 09-24 起点顶栏数据源直接跳到页签 |
| 左“平移探查” vs 页签“单点探查” | 前者是工具（在地图上点），后者显示结果 | 保留 |

09-24 用脚本检查过：1536×864、1366×768、1024×768 三个窗口尺寸，二维和三维视图下，没有任何按钮被别的元素挡住，也没有横向滚动条；1536×864、1707×930、1920×1080 下所有底部页签都不需要整体滚动（长表格在表格内部滚动）。

## 7. 原理、实现与指标

每一项按“做什么 → 怎么实现（代码位置） → 用到的理论 → 看什么指标”写。

### 7.1 高光谱数据与预处理

- **数据**：WHU-Hi 无人机高光谱数据集。每景是一个立方体 H × W × 270：每个像素有 270 个波段的反射光谱（约 400～1000 nm，界面上的波长按等间隔近似）。不同作物叶绿素、水分、结构不同，光谱曲线形状不同，这是能“按光谱认作物”的物理基础。
- **预处理**（`model/preprocess.py`，离线由 `model/export_scene.py` 导出 `cube_f32.bin`，地面站和板子用同一份）：
  1. 每个波段做 3×3 高斯平滑，核 `[[.05,.1,.05],[.1,.4,.1],[.05,.1,.05]]`，压掉单像素噪声；
  2. 逐波段减均值、除尺度，再整景整体标准化（照上游论文代码的写法）；
  3. 四周补 3 像素的零边，保证边缘像素也能取满 7×7 窗。
- **取窗**（`gcs/engine.py` `Scene.windows`）：每个像素以它为中心取 7×7 邻域 × 270 波段 = 13,230 个数，这是“空间—光谱”联合输入：中心像素的光谱加上周围的空间上下文。然后对这个 patch 整体减均值、除无偏标准差（patch 级归一化），消除光照强弱差异。
- **假彩色底图**：取第 112 / 67 / 31 波段（约 650 / 549 / 469 nm，接近红 / 绿 / 蓝）作 RGB，按 2%～98% 分位拉伸。

### 7.2 分类模型：Tensor Transformer

代码 `model/tt_model.py`，推理在 `gcs/engine.py`（PC 源，浮点）；板上是同一网络的定点版（`src/hls/`）。

1. **切 token**：7×7×270 的 patch 按波段交错切成 5 个子张量，每个 7×7×54（第 i 个取波段 i, i+5, i+10, …），再加一个可学习的 cls token，共 6 个 token，加位置编码。
2. **12 层张量编码层（TEL）**，每层：
   - token 归一化（每个 token 减均值、除标准差，无仿射参数）；
   - **张量投影**：Q、K、V 不是用一个 2646×2646 的大矩阵，而是沿三个轴分别乘 7×7、7×7、54×54 三个小矩阵（mode-n 乘积，Tucker 分解的形式）。一次投影只有 7²+7²+54² = 3,014 个参数，而全连接要约 700 万，这是模型小、适合放进 FPGA 的原因；
   - **自注意力**：6 个 token 两两算相似度 QᵀK，softmax 得到 6×6 注意力矩阵，再按权重汇合 V。探查页的“12 层注意力矩阵”就是这个 6×6；
   - 残差 + 归一化，再过一个同样是张量投影的 MLP，再残差。
3. **分类头**：取第 1 个光谱 token（不是 cls token，上游代码就是这么训的）展平成 2646 维，全连接到类别数，得到 logits。
4. **置信度** = softmax(logits) 的最大值，0～1。它是模型对自己判断的“把握”，**不是正确概率**（模型可能很自信地错）。

### 7.3 整景巡检 / 区域识别 / 评测

- **实现**（`gcs/server.py` `make_coords`、`gcs/sources.py`）：先生成要算的像素坐标表（整景 = 全部 H×W 按行；区域 = 矩形内按行；评测 = 测试掩码里的像素），每 1024 个一批送 GPU（或发给板子），结果按块经 WebSocket 推给浏览器，每像素 6 字节（行、列、类别、置信度）。浏览器每收到一块就画到地图上，所以能看到“推扫”效果。
- **理论**：推扫式（push-broom）高光谱相机本身就是一行一行成像的，逐行处理最贴近机载实时处理。
- **指标**：吞吐（像素/秒）、ms/像素、mJ/像素、结果量。

### 7.4 单点探查

- **实现**（`/api/probe` → `engine.probe`）：对一个像素单独前向一次，额外返回每层的注意力矩阵、各类概率、预处理后的光谱。“光谱曲线”里除了这个像素的光谱，还画出**判成的那一类**在训练集里的平均光谱（实线）；如果真值是另一类，再用虚线画出真值类的平均光谱。平均光谱只用官方 Train100 样本算，可以直观看出这个像素更像哪一类、为什么被判错。
- **指标**：类别、置信度、单像素推理耗时（PC，含传输）、是否与真值一致（仅评测）。

### 7.5 种植结构与面积

- **实现**（`panels.js` `P.stats` / `P.area`）：对当前显示的结果逐类数像素。
- **理论**：地面采样距离 GSD（Ground Sample Distance）是一个像素在地面上代表的边长，由航高和镜头决定。LongKou 航高 500 m，GSD 0.463 m，一个像素约 0.214 m²。面积 = 像素数 × GSD²，1 亩 = 666.67 m²。
- **指标**：各类面积、占比、平均置信度。

### 7.6 待核查斑块与补采样

- **低置信斑块**（`gcs/analysis.py` `patches`）：把“置信度 < 阈值”的像素做成掩码，用 **8 邻接连通域标记**（`scipy.ndimage.label`，上下左右加四个斜角都算相连）找出一块块区域，面积 ≥ 最小面积的保留。
- **孤立碎斑**：对每一类，找 3～12 像素的小连通块，取它向外一圈（形态学膨胀减去自身）；如果这圈里九成以上是别的类，判为孤立碎斑。逐像素分类常见的“椒盐噪声”就是这种，多半是误分。
- 两类合在一起，低置信在前、面积大的在前，最多 60 个；每个给出面积、中心、主类（块内最多的类）、平均置信度。
- **补采样**（`sampling`）：用 15×15 **均值滤波**（盒式滤波）算每个位置周围的平均置信度（只算已处理像素，窗内要有八成以上已处理），取最小的位置，然后把它周围一片置为无效再取下一个（**非极大值抑制**的思路，保证互不重叠），最多 5 个。
- **指标**：斑块数、低置信像素总面积、平均置信度。

### 7.7 地块台账

- **实现**（`panels2.js` `parcelRows`）：多边形顶点用图像坐标保存。对多边形外接矩形里的每个像素，取像素中心点，用**射线法**（从点向右发一条射线，与多边形边相交奇数次就在里面，偶数次在外面）判断是否在地块内，然后统计。
- **指标**：
  - 面积 = 地块内像素数 × GSD²
  - 已识别 = 有结果的像素 ÷ 地块内像素
  - 主栽作物、主栽占比 = 最多那一类占已识别像素的比例
  - 混杂比例 = 1 − 主栽占比
  - 低置信占比 = 置信度 < 0.6 的像素比例

### 7.8 精度指标

- **实现**（`gcs/analysis.py` `metrics`）：只取“已处理 且 属于官方测试集”的像素，数出**混淆矩阵** C：第 i 行第 j 列 = 真值是 i 类、被判成 j 类的像素数。
- **公式**（n = 测试像素总数）：
  - **OA 总体精度** = 对角线之和 ÷ n，即判对的比例。
  - **每类精度** = C[i][i] ÷ 第 i 行之和，即这一类里被找对的比例（召回率，遥感里叫生产者精度）。
  - **AA 平均精度** = 各类精度的平均。OA 会被大类主导，AA 让每类权重相同，更能看出小类表现。
  - **Kappa 系数** = (OA − pₑ) ÷ (1 − pₑ)，其中 pₑ = Σ(第 i 行之和 × 第 i 列之和) ÷ n²，是“随机乱猜也能碰对”的比例。Kappa 衡量扣除偶然一致后的一致程度，1 为完全一致，0 相当于随机。
- **官方划分**：Train100 = 每类 100 个训练像素，Test100 = 其余有标签像素。训练和测试不重叠，测试集只用于评测。
- **实时刷新**：任务运行时每 1.5 s 按当时已处理的测试像素重算一次，所以能看到 OA 随进度收敛。

### 7.9 历史对比

- **实现**（`analysis.compare`）：两次结果都已处理的公共像素里，数类别不同的像素（变化像素）；在有真值的像素上分别算两次的精度。滑动对比是把两张结果图叠在一起，按中线位置分别裁剪显示。
- **指标**：公共像素、变化像素及比例、A / B 各自的精度（真值仅评测）。

### 7.10 闭环更新（模型微调）

- **设定**（`model/finetune_region.py`）：旧模型 hold3 训练时去掉了芝麻，模拟“新地块种了训练集没见过的作物”。核查区是芝麻像素最多的 64×64 窗口，用**积分图**（二维前缀和，任意矩形求和只要 4 次加减）以步长 4 滑动搜索得到。
- **标注点**：取芝麻在官方 Train100 里的像素，先取核查区内的，不够再按到区域中心的距离补足，共 30 个。不碰测试集。
- **微调**：从旧权重出发，训练集 = 原训练集 + 30 个标注点，交叉熵损失，Adam 优化器，学习率 2e-4 余弦退火，30 轮，按验证集选最好的一轮。这是**迁移学习 / 增量微调**：少量新样本加旧知识，比从头训练快得多。
- **验证**：官方测试集只评一次，前后对比 OA、AA、芝麻类精度、核查区精度、核查区芝麻召回、变化像素。然后用和板上相同的导出函数生成权重包。

### 7.11 权重下发与传输校验

- **权重包**：五个文件按顺序拼接（`weights_all`、`cls_token`、`pos_embed`、`classifier_w`、`classifier_b`），LongKou 约 448 KB。
- **分块**（`gcs/protocol.py` `weight_chunks`）：每块 = 12 B 公共包头 + 16 B 分块头（景号、槽位、偏移、总长、整包 CRC）+ 最多 1384 B 数据。
- **停等式 ARQ**（`sources.BoardSource.upload_weights`）：发一块、等 ACK，0.5 s 没等到就重发，最多重发 3 次。简单可靠，代价是每块都要等一个往返。
- **CRC32 校验**：对整包算 32 位循环冗余校验（和 zip、以太网同一多项式）。板子收齐后自己算一遍，一致才接收。CRC 能检出所有 ≤ 32 位的突发错误，绝大多数随机错误也能检出。

### 7.12 UDP 协议与链路统计

- **包格式**（`gcs/protocol.py`，草案 v0）：12 字节公共头（魔数 `HE`、类型、版本、任务号、序号）。结果包 ROW = 行号、起始列、像素数 + 每像素 4 字节，一包最多 348 个像素；每像素 4 字节 = 低 8 位类别 + 高 16 位置信度（Q0.16 定点：置信度 × 65536，分辨率约 0.000015）。
- **为什么用 UDP**：延迟低、实现简单，适合裸机 lwIP；可靠性靠序号、ACK、CRC 自己补。
- **统计**：收发包数和字节数；丢包 = 序号缺口；2 s 内收到过包算“在线”。
- **链路压缩**：原始立方体每像素 270 × 2 字节 = 540 B，分类结果 4 B，135 : 1。这正是“边缘计算”的意义：在机上算完只回传结果，链路压力小两个数量级。

### 7.13 三维立方体

- **实现**（`gcs/web/cube.js`）：用 CSS 3D 变换把 5 张画布拼成一个长方体。顶面 = 假彩色 + 分类叠加；侧面每一列是一个边缘像素、每一行是一个波段，数值按整景 1%～99% 分位映射到色标。“剥离”时顶面换成第 b 个波段，高度变成 270 − b。
- **意义**：直观展示“高光谱 = 每个像素一条光谱曲线”，侧面的条纹就是光谱随波长的变化。

## 9. 常见问题

**现场微调特别慢（十几分钟以上）**
GPU 被别的任务占着（比如 QAT 训练、`qat_eval`）。09-24 实测：别的训练在跑时，每轮从 1 s 变成 14～40 s。先用 `nvidia-smi` 看利用率，演示前确保没有别的训练在跑；来不及就用“用已验证 v3”。

**模拟板一启动就退出，报 `WinError 10054`**
Windows 的 UDP 特性：往没人监听的端口发包后，下一次收包会报这个错。09-24 已在 `fake_board.py` 里处理，现在先开模拟板、后切板卡源也没问题。

**切到板卡源后提示“板卡源打开失败（端口占用？），退回 PC 源”**
本机 UDP 5011 被别的程序占了（比如另一个地面站服务）。用 `Get-NetUDPEndpoint -LocalPort 5011` 找到占用的进程。

**切到真板后链路一直“断开”**（未实测，排查方向）
检查网线、本机和板子 IP 是否在同一网段、Windows 防火墙是否放行 UDP 5011 入站。

**历史对比里选某条提示“已被服务端清理”**
服务端只保留最近 16 次任务。09-24 起超出的会自动从表里去掉，正常不会再碰到。

**模拟板上复测“现场微调”生成的新版本**（根据代码推断，未实测）
模拟板的版本表只在启动时读一次，不认识地面站运行中新生成的 `live...` 版本，大概率会出错。现场微调出的新版本先在 PC 源复测；真板上是按下发的槽位加载，不受这个限制。
