# KEY5 / KEY6 操作

用户确认：KEY5 是 PS 用户键（MIO26），KEY6 是 PL 用户键（AF12），KEY7 是硬件复位键。

| 按键 | 单击 | 双击 | 持续按住 2 秒 |
|---|---|---|---|
| KEY5 | 当前场景随机单点真实 PL 探查 | 整景巡检 | 切换场景 |
| KEY6 | 随机矩形区域识别 | 随机多边形地块及其外接矩形识别 | 切换场景 |
| KEY7 | 保留原复位功能 | 不定义业务操作 | 不定义业务操作 |

PC 后台服务必须运行并已经连接板卡；可以关闭浏览器。按键事件走现有唯一以太网连接，由同一个后台任务入口登记和下发，不开第二个 UDP 任务控制者。启动网页本身不触发推理。

## 手势

- GPIO 采样最多每 5 ms 一次，稳定 25 ms 确认电平变化。
- 连击等待窗口 350 ms；两次短按只执行双击，三次连续短按忽略。
- 满 2 秒执行一次切景；持续按住不连发，释放也不补发单击。
- 上电时已按住的键要先释放；两个键同时按下不执行组合操作。
- 在 PL 等待、SD 服务和镜像编码过程中继续采样，识别器没有阻塞延时。

## 任务及统计

- 场景按龙口 → 洪湖 → 汉川循环，优先选择该场景已登记的模型。长按先确认原任务安全停止、保留部分结果，再选择场景。切景不会自动开始推理，也不在此时读完整高光谱数据；下一次真实 START 仍会加载、校验输入和激活模型。新场景首次准备约 15～40 秒，以实际板端回传为准。
- 原区域或整景仍在运行时，单点探查使用独立探查通道，不改变已处理像素、区域分类统计和台账覆盖率。
- 没有可复用任务时，单点沿用现有网页的真实 1×1 任务加完整 PL 探查流程。
- 正在运行的任务不会被新的随机区域或整景请求覆盖；DP 和 PC 明确提示忙碌。
- 随机矩形按当前场景 GSD² 计算，面积不超过 6000 m²；另设默认 4096 像素演示上限。面积上限不意味着每次都生成接近 6000 m² 的区域。
- 随机地块是 3～5 顶点的有效凸多边形，外接矩形同样满足限制。地块逐一追加到 PC 台账，不覆盖手工地块；台账版本冲突保留原文件并报告错误。
- 推理范围是外接矩形；选中地块的面积、占比和覆盖率只计算多边形内部真实收到的分类结果。单点探查不加入地块统计。
- 浏览器有未保存的地块编辑时，保留草稿并提示用户；不强制切景或覆盖编辑内容。

## 传输

按键事件 0x8b：28 字节，含启动、会话、事件序号、按键、手势、场景；PC 回执 0x17：28 字节，含同一身份及接收/执行/拒绝状态。校验唯一已有 UDP 对端，重复事件只重发回执，不重复启动任务。迟到的接收回执不能覆盖执行终态。

板端最多等待 PC 接收 5 秒；超时显示后台离线。PC 接收后，板端仍用相同事件号查询执行回执，避免末次回执丢失导致提示停留在“已接收”；最多观察 180 秒，不重复启动动作。实际任务仍按原 ACK/STATUS、CLASS 和完整探查回传确认。按键流记录在连接日志，任务日志只保留实际任务命令及真实结果。

DP 顶部保留 PC 通信状态；左下方改为“任务下发状态”，区分 PC、KEY5/KEY6 单击、双击、长按，显示具体动作和接收、准备、执行、完成、停止、失败等状态。下方常驻按键说明。来源由实际 START、PROBE、控制命令和按键事件/回执关联，页面刷新不会产生一条假任务。

网页自动同步任务范围、探查位置和地块，日志中记录操作及失败原因；任务卡附近显示准备提示。切景等待页清除当前图层/进度选择，但原任务留在历史中。连接保持期间持续心跳，避免空闲五分钟后按键入口失效。

三景类别均使用中文显示；洪湖、汉川保留原类别 ID、颜色和顺序。洪湖蔬菜名称是对应英文类名的显示译名，不合并类别。例如 Pakchoi 为“小白菜”、Brassica chinensis 为“青菜”、Small Brassica chinensis 为“小青菜”。
