## 2. 先向用户讲这一条主链（当前实现，不是未来设想）

```text
PC 上的 WHU-Hi 原始 .mat 数据和已有 checkpoint
  └─ PC 离线预处理/导出（不是每次任务都训练或预处理）
       ├─ cube_f32.bin + 模型二进制包 → SD 卡
       └─ GT、官方划分、假彩色/元信息 → PC 显示和评测

板卡 SD：1:/scenes/<scene>/...
  └─ PS（A53 裸机）读文件、检查大小/CRC
       ├─ 当前场景 float32 cube → 板载 DDR 的 CPU 输入缓存
       ├─ 模型登记/暂存 → DDR；激活时拷至专用权重缓冲并 LOAD_W
       └─ 每个中心像素：取 7×7×270 → 逐窗归一化
            → 拼 CLS/位置编码、量化 int16 → DDR 输入缓冲
                 └─ PL 的 tt_engine：12 层 Transformer + 分类头
                      → CLASS/logits/可请求的注意力结果 → DDR 输出缓冲
                           └─ PS 校验/读取并保存实际结果
                                ├─ 本地绘图 → DDR 帧缓冲 → DPDMA/DP → 显示器
                                └─ UDP 增量结果/状态 → PC 地面站
                                     → 地图、图表、农情分析、精度评测、历史对比
```

**控制链另走一条**：当前主要由 PC 地面站明确发送任务/模型/暂停停止/单点命令，经以太网到 PS；不是 PC 每算一个像素再喂板卡。任务开始且数据就绪后，主体计算和 DP 更新在板上继续，所以断网不等于推理停止。断网期间 PC 的控制命令无法送达。

### 哪类数据在哪

| 数据 | 当前存放/使用位置 | 说明 |
|---|---|---|
| 原始高光谱、GT、Train100/Test100 | 主树 `data/raw/WHU-Hi/Matlab_data_format/...`；运行树有精确需要的副本 | 当前样机用真实数据集文件，不能说已接上实时机载高光谱相机 |
| 离线预处理后的整景 | PC `data/scenes/<scene>/cube_f32.bin`；SD `1:/scenes/<scene>/cube_f32.bin` | 高斯/全景归一化、270波段、3像素零边；不是原始.mat直接交给PL |
| 当前整景缓存 | PS 可访问的板载 DDR，`roi_runtime.cpp::cube` | 只常驻当前场景；最大缓冲491428080 B，约468.66 MiB，不是把三景同时放进片内BRAM |
| 模型 | PC checkpoint/导出包；SD `1:/scenes/<scene>/weights/<tag>/`；板上登记缓存和专用权重缓冲 | 启动扫描模型，选模型/场景后才按需读 cube；同景可复用DDR |
| 一批推理输入 | PS 的 patch/int16 输入缓冲（DDR） | PS做取窗、归一化、CLS/位置编码、量化；普通任务每步最多4个中心点且不跨任务行 |
| 神经网络主体 | PL `tt_engine` | 当前FULL路径含12层和分类头；不是只用FPGA搬数据，也不是PC计算完再给DP显示 |
| 分类结果 | 板上DDR结果库，CLASS为4B/像素；PC接收后另有结果缓存 | DP和UDP均使用已提交的同一份真实结果，不用GT填色 |
| DP图像 | PS写DDR中的1920×1080 RGBA帧缓冲，PS DPDMA/DisplayPort输出 | DP本身是显示接口，不是另一个推理处理器 |
| GT/测试划分 | PC评测链 | 不作为板上分类输入；GT并排与Test100指标口径分开 |
| S1～S5建议点 | PC对实际分类/置信度做业务分析 | 默认5个低置信度15×15邻域中心；不是自动训练点、不是病害判断 |
| 训练/微调 | PC的PyTorch路径，使用已有/明确选择的标签 | 不是当前板上推理的必要步骤；按用户最新取舍降为非核心 |

板上DDR是CPU和PL交换输入/输出的外存；驱动维护cache一致性。PL走当前嵌入后的int16输入路径，而不是读取GT、浏览器图片或.mat文件。
