|---|---|---|---|---|
| 0x01 | START | 地→板 | `<BBBBHHHH` 12 B：mode, scene, weights, pad, row0, col0, rows, cols | mode 0 整景 / 1 区域 / 2 单点 / 3 评测（`protocol.py:37`）；scene = `model/scenes.py` SCENES 的顺序（0 longkou、1 honghu、2 hanchuan）；**weights = 地面站 `engine.VERSIONS[scene]` 列表下标**（`sources.py:201-203`，模拟板按同一列表反查，`fake_board.py:90-91`）；整景时矩形忽略 |

| 0x83 | ACK | 板→地 | `<BBHI` 8 B：acked_type, code, pad, value | 目前只回 WCHUNK：code 0 成功 / 1 CRC 错，value = 已收字节 off + len（`fake_board.py:100-110`） |

### 1.3 行为

- **任务**：START 抢占正在跑的任务（模拟板先置停止事件再起新线程，`fake_board.py:85-93`）；模拟板每 1024 个像素推理一批，按行段发 ROW。
- **完成判定**：地面站收到本任务 STATUS state = 3 立即回调 `on_done('done')`（`sources.py:186-190`），**不核对像素是否收齐**。
- **丢包统计**：地面站按板卡序号缺口累加，只统计当前任务号的包，且只认 0 < 缺口 < 1000（`sources.py:172-176`）；START 时清掉上一个序号（`sources.py:198`）。
- **在线判断**：2 s 内收到任何包算在线（`sources.py:143-144`）；地面站不主动发心跳。
- **权重下发**：停等 ARQ，每块最多发 4 次、每次等 ACK 0.5 s（`sources.py:217-237`）。模拟板在 offset = 0 或总长变化时重置缓冲，末块到达时算整包 CRC32（`fake_board.py:103-108`）；不落盘、不切换。地面站收齐 ACK 后顶栏自动切到该版本（`web/panels2.js:135`）。
- **Windows 10054**：模拟板收包循环捕获 `ConnectionResetError`（`fake_board.py:79-80`）；地面站 `_rx` 捕获 `OSError`（`sources.py:163`）。
- **链路面板**：收发包数与字节、序号缺口；柱状图"原始立方体 270×2 B : 分类结果 4 B = 135 : 1"与实收 UDP 字节（`web/panels2.js:140-157`）。

已验证（09-24，PC 与模拟板，非板上；`docs/gcs_guide.md` §10）：区域识别板卡源对 PC 源 4096/4096 标签一致、置信度最大差 1/255；权重下发 458,724 B、CRC32 通过（本机 0.09 s）；评测 203,642 像素 OA 0.9384；暂停 / 继续 / 停止、连续任务。

### 1.4 v0 的缺口（读代码得出，未逐项复现）

1. 丢了 ROW 不补；最后几包 ROW 丢失时，任务照样被判"完成"但缺像素。
2. 命令不确认：START 丢了，地面站一直等；STOP 丢了，板卡继续算，地面站却已显示停止。
3. 没有时间戳，算不了 RTT 与单向时延；没有心跳，板卡不知道地面站是否在线，"断线期间继续处理、恢复后补传"无从做起。
4. 版本号耦合：START.weights 与 WCHUNK.slot 是地面站 Python 列表下标，真板 SD 上的 `weights/<版本>/` 目录没有这个编号。
5. 权重包只有五文件拼接一种（M1 / M2 路径用）；M3 引擎要 `weights_engine.bin`（int16 480,576 B / int8 336,064 B，`tt_engine_regs.h:60-77`）。LongKou 的 v3、v3_ft50（闭环演示用）目前只有 `weights_all.bin`，没有 `weights_engine.bin`。
6. 模拟板不等地面站就往固定地址发 STATUS，这是 10054 的起因；真板照此写就得把 PC 地址写死（pose6d 就写死了 192.168.1.102，`net_udp.cpp:27-34,136-140`）。
7. 单点探查：`protocol.py:37` 定义了 START mode 2，但 START 会抢占正在跑的任务；`server.py` 的 `make_coords` 不接受 probe（`server.py:251-261`），地面站探查固定走 PC（`server.py:201-206`）。

## 2 v1 设计（09-26 评审修订）

### 2.1 原则

- 板端：裸机 standalone，lwIP raw API，A53 单核 + GEM 中断起步。收包回调在主循环调用 `xemacif_input()` 时执行（pose6d 的 `net_poll`，`net_udp.cpp:151-154`），不在中断里；计时统一用 `XTime_GetTime()`；不用线程、信号量、套接字 API 等依赖操作系统的机制。E3 多核后网络归核 2，核间走 OCM 环形缓冲，线上格式不变。
- 结果**先落 DDR 再发**；实时发送尽力而为，完整性由地面站按行号拉取补齐（§2.6）。
- 命令全部确认、可重发、重复执行无副作用。
- 包头布局不变，新字段只占 v0 的保留位或追加在包体末尾，v0 的解析代码（`unpack_from`）读 v1 包不出错。

### 2.2 公共头 v1（12 B，布局同 v0）

| 偏移 | 字段 | v1 语义 |
|---|---|---|
| 0 | u16 magic | 0x4548 |
| 2 | u8 type | 见 §2.3 |
| 3 | u8 ver | 1；收端接受 0 与 1，其他计为格式错误 |
| 4 | u16 task | 任务号（地面站分配）；与任务无关的包填当前任务号 |
| 6 | u16 seq | 发送方序号，每发一包加 1，**整个会话连续**（不因任务清零）；比较用模 2¹⁶ 的差 |
| 8 | u32 t_us | 发送时刻：发送方单调时钟的微秒数低 32 位（板卡由 `XTime_GetTime()` 换算，地面站 `time.perf_counter_ns() // 1000`）；71.6 min 回绕，只用差值 |

会话：地面站每次打开板卡源生成随机 u32 `session`（PING、START 携带）；板卡每次上电生成随机 u32 `boot_id`（STATUS、INFO_R 携带）。任一方换了，对方把序号基准清零、不计丢包；boot_id 变了，地面站把在飞任务判"板卡重启"。

### 2.3 包类型 v1

加粗为新增或改动，未列出的字段同 v0。地→板命令都回 ACK（PING 回 PONG，INFO 回 INFO_R，PROBE 回 LOGITS）。

| type | 名称 | 方向 | 包体 | 说明 |
|---|---|---|---|---|
| 0x01 | START | 地→板 | v0 12 B + **u32 wcrc + u32 session** | wcrc = 权重包 CRC32，≠ 0 时忽略 weights 下标；板卡以 (session, task) 去重：与最近一次执行过的 START 相同（不论该任务在跑、已停还是已完成）只回 ACK、不重启 |
| 0x02～04 | STOP / PAUSE / RESUME | 地→板 | 无 | 头里 task = 当前任务才执行，否则回 ACK code 9、不执行；置状态，同一条重复执行无副作用；在当前行结束后生效；重发规则见 §2.7 |
| **0x05** | PING | 地→板 | u32 session | 250 ms 一包；板卡记下源 IP:端口，作为之后所有回包的目的地址 |
| **0x06** | ROWREQ | 地→板 | u16 n, u16 pad, n × {u16 row0, u16 nrows}，n ≤ 349 | 按图像行号补传本任务（头里的 task）**已产出**的行；收到即回 ACK，value = 排进补传队列的行数（未产出或已回收的行不排）；新的 ROWREQ 替换还没发完的队列；补齐与否由地面站按完成掩码判断 |
| **0x07** | INFO | 地→板 | 无 | 查询板卡版本、权重表、当前任务 |
| **0x09** | PROBE | 地→板 | u8 scene, u8 pad, u16 row, u16 col, u16 pad, u32 wcrc | 单点探查：在当前这次计算调用结束后插算这一个像素（M3 起一次调用 = 一行），不改任务状态、不动 front_row；wcrc = 0 用当前权重，否则临时装载该版本、算完装回（单库下各约 0.3 ms）；回 LOGITS（代替 ACK）；无此权重回 code 5，坐标越界回 code 8 |
| 0x10 | WCHUNK | 地→板 | 同 v0 | v1 规则：offset 必须等于已收字节（或是重复的上一块），否则回 code 2、value = 期望偏移；slot 字段填 kind、收端忽略（v0 是 VERSIONS 下标） |
| **0x11** | WBEGIN | 地→板 | u8 scene, u8 kind, u16 pad, u32 total, u32 crc32, char tag[16] | kind 见 §2.8；crc 与暂存区相同 = 续传，ACK value = 已收字节 |
| **0x12** | WCOMMIT | 地→板 | u32 crc32 | 板卡校验并登记，见 §2.8 |
| **0x13** | WACT | 地→板 | u8 scene, u8 when, u16 pad, u32 crc32 | when 0 = 下一任务起用；1 = 下一行边界（双库热切换），ACK 在实际切换时发、value = 第一个用新权重的行 |
| 0x81 | ROW | 板→地 | 同 v0，**pad → flags** | bit0 = 补传；其余位 0 |
| 0x82 | STATUS | 板→地 | v0 24 B + **v1 尾部 56 B**（§2.9 表 A） | 在线 250 ms 一包，断线 1 s 一包 |
| 0x83 | ACK | 板→地 | acked_type, code, **acked_seq**（v0 的 pad）, value | code：0 成功、1 CRC 错、2 偏移不连续、3 包头不符、4 已校验但 SD 没写成（DDR 可用）、5 无此权重、6 装载失败（value = 引擎返回值）、7 任务结果已回收、8 参数非法、9 任务号不符（未执行） |
| **0x84** | PONG | 板→地 | u16 ping_seq, u16 pad, u32 t1, u32 t2 | t1 = PING 头里的 t_us 原样回显，t2 = 板卡收到 PING 的时刻；PONG 头里的 t_us 即 t3 |
| **0x85** | LOGITS | 板→地 | u16 req_seq, u8 scene, u8 ncls, u16 row, u16 col, u32 wcrc, u32 class, ncls × i32（Q.16） | PROBE 的回复：req_seq = PROBE 头里的 seq，class 与 ROW 同字，logits 同 engine_arch §5.2 的 LOGITS 输出；M1 起板卡各路径都回（M1 / M2 由 PS 算出 logits，M3 起引擎 OUT(LOGITS)、n_patch = 1）；引擎不输出注意力矩阵，板卡源下探查面板的注意力热力图仍由 PC 算，标"PC 参考" |
| **0x86** | INFO_R | 板→地 | u32 boot_id, u8 协议版本, u8 引擎契约版本, u8 片上位宽, u8 条目数；当前任务 24 B（session、task、mode、scene、矩形、wcrc、front_row、state）；条目 × 28 B {u8 scene, u8 kind, u16 pad, u32 bytes, u32 crc32, char tag[16]} | 一包最多 48 条 |
| 保留 | 0x08 CLOCK（E5 性能档）、0x87 ROW_RLE（E1r 行程编码） | | | 本版不定义 |

### 2.4 心跳与断线检测

| 参数 | 值 | 理由 |
|---|---|---|
| 地面站 PING 周期 | 250 ms | 与服务端 ticker 0.25 s（`server.py:105`）同拍；每秒 4 包 × 16 B，可忽略 |
| 板卡 STATUS 周期 | 在线 250 ms（空闲也发），断线 1 s | 在线时送进度与计数器；断线时降频作信标 |
| 断线判定 T_down | 1.0 s 未收到对方任何合法包，两端相同 | = 4 个心跳周期；丢包率 10⁻³ 时连丢 4 包的概率 10⁻¹²；Python 调度抖动几十 ms ≪ 1 s。现值 2.0 s（`sources.py:144`），§5 第 3 条定 1.0 s。地面站线程若被占住 > 1 s，板卡会误判断线，代价只是停发与多一条断线记录，结果仍靠补传收齐 |
| 恢复判定 | 收到对方第一个合法包 | 不另设滞回，抖动由 T_down 吸收 |

| 事件 | 板卡 | 地面站 |
|---|---|---|
| 判断线 | 计算照常，结果照常写 DDR（DP 照常画）；停发 ROW；STATUS 降到 1 s；`udp_send` 失败只计 tx_fail、不重试（pose6d `send_one` 遇 ERR_MEM 最多重试 2000 次，`net_udp.cpp:51,176-201`，断线时会拖住主循环） | 顶栏显示"断开"，记 t_down（最后一次收包时刻）；在途命令按各自的重发次数继续；此后的序号缺口记入"断线丢包" |
| 恢复 | 从当前产出行起继续实发 ROW，**不主动推积压**；回包地址改为最新 PING 的源地址 | 记 t_up；按 STATUS 对账（task、state、wcrc 与本地期望不符就重发对应命令）；对缺口发 ROWREQ（§2.6） |
| 板卡重启（boot_id 变） | — | 在飞任务判 `error:板卡重启`；经 INFO 重读权重表 |

板卡上电后**不主动发包**，收到第一个 PING 才开始回 STATUS：不用写死地面站地址，地面站没开板卡源时也没有包打到 5011，不会产生 10054。PHY 链路状态若 lwIP 适配层能读到，只放进 STATUS 的 link 字段作诊断，不参与判定（C3b 上板时确认能否读到）。

**不用环形缓冲，按任务存整幅结果**（§5 第 2 条）：每个任务一个 2 MB 槽（≥ HongHu 1,786,000 B），按 (row, col) 直接寻址，4 个槽轮换，共 8 MB（DDR 4 GB 的 0.2%）。槽头记 session、task、mode、scene、wcrc、矩形、front_row、state。任务按行主序产出，"front_row 之前的行已全部产出"一个数就够，不需要逐行位图；评测任务的像素稀疏，同样按 (row, col) 存。补传直接从槽里读；槽被第 5 个任务覆盖后再请求，回 code 7。环形缓冲只在断线期间的结果可能超过缓冲容量时才有必要，这里整幅都放得下；整幅槽还能顺带给 DP 监视器当画面源、给重启后的地面站取回结果。

### 2.6 补传：缺口检测与两种方案

地面站判断缺口：任务的期望像素集合已知（`server.py` 的 `run.coords`，完成掩码 `run.done`），STATUS 给出 front_row；**缺口行 = front_row 之前、期望像素没收齐的行**，合并成区间。

| | A 选择性重传（地面站按行号拉取） | B 从断点续传（板卡按累计确认回退） |
|---|---|---|
| 做法 | 地面站发 ROWREQ 列出缺口区间，板卡从结果槽读出补发 | 地面站在 PING 里带"第一个没收齐的行 k"；板卡恢复后把发送指针退回 k，其后全部重发 |
| 板卡状态 | 结果槽 + front_row，无确认状态 | 每任务一个发送指针 + 确认处理 |
| 30 s 断线补传量 | 缺口行（估 84～521 行，≤ 617 KiB） | 同左，另加 k 之后已经收到的行 |
| 零星丢一包 | 只补这一行 | 累计确认卡在这一行，要超时回退，其后的行全部重发 |
| 任务末尾丢包、地面站重启 | 同一机制（INFO 取任务描述 + ROWREQ） | 要另加机制 |
| 恢复后开始补传 | 等地面站收到第一包 STATUS（≤ 250 ms）再请求 | 板卡收到 PING 即开始 |
| 实现量 | 板卡：解析区间、按行读槽发送；地面站：由掩码求区间 | 板卡：指针、回退、确认；地面站：去重 |

**用 A**（§5 第 1 条）。触发：① 恢复后收到第一包 STATUS 立即请求；② 运行中每 1 s 查一次（零星丢包）：只请求 0.5 s 以前收到的 STATUS 就已越过（行号 < 那包的 front_row）、至今仍缺、且距上次请求已超过 0.5 s 的行，给还在路上的包留时间；③ 收到 state = 3 后循环请求直到收齐，最多 5 轮，仍缺则任务结束为 `error:缺 n 像素`。**收齐且 state = 3 才判完成**（改 `sources.py:186-190`）。板卡补发优先级低于实时行，每轮主循环最多发 8 包（pose6d `net_frame_step(8)` 的做法，`net_udp.h:103-124`）；ROWREQ 收到即回 ACK，不等补发完（§2.3）。

### 2.7 命令确认与超时重发

| 命令 | 板卡动作 | ACK value | 超时 × 发送次数 | 重复收到时 |
|---|---|---|---|---|
| START | 抢占旧任务，行边界开始新任务 | 0 | 300 ms × 4 | (session, task) 与最近一次执行过的 START 相同 → 只回 ACK |
| STOP / PAUSE / RESUME | task = 当前任务才执行；置状态，当前行结束后生效 | 当前 front_row（task 不符回 code 9、不执行） | 300 ms × 4 | 再执行一次，无副作用 |
| ROWREQ | 把区间内已产出的行排进补传队列，替换还没发完的队列 | 排队行数（收到即回） | 300 ms × 4，每次按最新缺口重算 | 按新列表替换队列 |
| INFO | 回 INFO_R（代替 ACK） | — | 300 ms × 4 | 再回一次 |
| PROBE | 在调用边界插算一个像素，回 LOGITS（代替 ACK） | — | 1 s × 3（要等当前这次调用算完，M3 一行约 0.1～0.4 s） | 再算一次，结果相同 |
| WBEGIN / WCHUNK | 见 §2.8 | 已收字节 | 300 ms × 4 | 按偏移判重 |
| WCOMMIT | 校验、登记，空闲时同步写 SD | bit0 = 已落盘 | 5 s × 1（写 SD 耗时 C3a 实测后再定） | 已提交同一 crc → 直接回 0 |
| WACT | 切换权重 | 第一个用新权重的行 | 300 ms × 4 | 已是该版本 → 回 0 |

- 300 ms 的依据：直连网线 RTT 应在毫秒以下（待实测）；关键在板卡主循环等 `ap_done` 时也要跑 `xemacif_input()`（每 ≤ 10 ms 一次），否则命令要等一整行算完（估 0.1～0.4 s）才被处理。300 ms 对 10 ms 有 30 倍余量。
- **控制命令（START / STOP / PAUSE / RESUME）同一时刻只让一条处在重发状态**：发新的就取消旧的重发；重发的包沿用原包的 task（seq 照常加 1）。否则有两种错：PAUSE 的 ACK 丢了、随后发了 RESUME，迟到重发的 PAUSE 又把板卡停下，界面却显示在跑；STOP 重发时若填当时的任务号，会停掉刚开始的新任务。直连网线上包不乱序，这一条加上板卡按 task 过滤就够，不需要板卡比较序号新旧。
- 发送次数用尽仍无 ACK = **指令超时**：地面站计数并提示；STOP 超时显示"板卡未确认停止"，不再像 v0 那样本地直接判停。链路恢复后按 STATUS 对账再发。
- ACK 按 acked_seq 对应到具体哪一次发送；v0 按类型匹配（`sources.py:191-194`），两条同类命令同时在途时会错配。

### 2.8 权重包：分块、校验、原子切换与重载

| kind | 内容 | 字节 | 1384 B 块数 | 用于 |
|---|---|---:|---:|---|
| 0 | `weights_all│cls_token│pos_embed│classifier_w│classifier_b`（现有） | LongKou 458,724 | 332 | M1 / M2（PS 要 float32 的 cls、pos、分类头）；M3a 只用其中的 cls、pos |
| 1 | `weights_engine.bin` int16（`tt_engine_regs.h:60-77`） | 480,576 | 348 | M3（M3a 的 PS embed 另要 kind 0 里的 cls、pos） |
| 2 | `weights_engine.bin` int8 | 336,064 | 243 | M4 |

流程（板卡在 DDR 留 1 MB 暂存区；任何一步失败都不动在用的版本）：

| 步骤 | 板卡检查与动作 | 失败 |
|---|---|---|
| WBEGIN | scene、kind 合法，total ≤ 1 MB；crc 与暂存区相同 → 续传，回已收字节；否则清空暂存区 | code 8 |
| WCHUNK × N | offset = 已收字节才写入；重复的上一块只回 ACK | code 2 + 期望偏移，地面站从该偏移续发 |
| WCOMMIT | 长度 = total；整包 CRC32 = crc；kind 1 / 2 再查包头：magic 'TTE2'、位宽 = 编译的 TT_NUM、ncls = 该景类别数（即引擎 ERR_WPKG 的条件，`tt_engine_regs.h:129`）。通过后登记进权重表；空闲时立即写 `/scenes/<景>/weights/<tag>/<文件>.tmp` → `f_sync` → `f_rename`，任务运行中则等任务结束再写（写 SD 会阻塞单核主循环） | code 1 / 3；code 4 = 已校验、DDR 可用但 SD 没写成 |
| WACT | when = 0：下一个 START 前 LOAD_W（估 0.3 ms，engine_arch §4.4）；when = 1：双库编译下装入非活动库，行边界翻 USE_BANK，STATUS 的 wcrc 随之变 | code 5 / 6，继续用旧版本 |

- **版本标识用整包 CRC32**：地面站对自己的文件算 CRC32；板卡上电扫 `/scenes/*/weights/*/` 逐个算 CRC32 建表（INFO 回报）；START 与 WACT 都按 crc 指定。地面站版本列表的顺序因此与板上目录无关；tag 只作显示与目录名。100 个版本内 CRC32 碰撞概率约 10⁻⁶（生日界 n²/2³³）。
- **同一版本的配套包**：同一个 `/scenes/<景>/weights/<tag>/` 目录算一个版本，里面可以同时有 kind 0 与 kind 1（或 2）。START、WACT、PROBE 的 crc 指定引擎用的那个包（M1 / M2 为 kind 0，M3a / M3b 为 kind 1，M4 为 kind 2），板卡从同一目录取配套包：M3a 的 PS embed 要 kind 0 里的 cls、pos；配套包缺失回 code 5。WBEGIN 带 tag，下发的包落进对应目录。
- **原子性**：没通过 WCOMMIT 的包不可能被 WACT；WACT 只在任务或行边界生效；旧目录不删，回退 = WACT 旧 crc。FAT 没有日志，tmp + rename 只能缩小掉电窗口，不能消除。
- **重载**：切景或 WACT 时从 DDR 里的包 LOAD_W；上电从 SD 读入。
- 热切换（when = 1）下同一任务前后两段权重不同，地面站按 WACT 的 ACK value 记分界行；默认 when = 0；双库热切换做不做，D4a 的 Vivado 结果出来后再定（§5 第 7 条；引擎当前只实现单库，`tt_engine.h` 的 TT_W_BANKS = 1）。
- 停等仍然够用：块数 243～348，每块一个往返；本机模拟板 458,724 B 用 0.09 s（PC 实测），真板耗时待测，不够再改滑动窗口。

## 3 约束、兼容与迁移

### 3.1 板端（裸机）

- 主循环：`xemacif_input()` → 处理命令 → 引擎完成则 invalidate x_out、把这一行拷进结果槽并实发 ROW → 补发（≤ 8 包）→ 到点发 STATUS → 查 T_down。等 `ap_done` 期间也跑这个循环（或引擎中断只置标志），不能死等。
- 静态 IP 192.168.1.10（与 pose6d 同网段）；回包用 `udp_sendto` 发往最近一个 PING 的源地址，不用 `udp_connect` 写死 PC 地址。
- lwIP BSP 参数先照 pose6d PITFALLS E1（pbuf_pool_size 16384、memp_n_pbuf 1024、mem_size 524288、n_rx_descriptors 512，7020 上验证过），改完看 BSS 与链接脚本。本项目流量小得多（整景每行 1～2 包），补发靠限速而不是靠大池。
- pose6d 没调 `sys_check_timeouts()`（纯 UDP + 静态 IP 用不到，`net_udp.cpp:99-104`），ARP 表项不老化；换一台地面站笔记本会发到旧 MAC。是否周期调用，C3b 定。
- lwIP 收到 ICMP 不可达只计数丢弃、不通知 UDP pcb（lwIP 2.x `icmp.c` 的行为，上板确认），板端没有 10054 这类问题。
- 写 SD 会阻塞单核主循环，所以 WCOMMIT 在任务运行中只登记、不落盘（§2.8）。

### 3.2 Windows 地面站

- 收包循环继续捕获 10054（`ConnectionResetError`），单独计"对端端口不可达"次数作诊断（多半是板上程序没跑），不算收到包、不刷新在线状态。
- 板卡上电静默、收到 PING 才回包；地面站没开板卡源时，就没有包打到 5011。
- 保持 `SO_RCVBUF` 8 MB（`sources.py:119`）；防火墙放行 UDP 5011 入站（`gcs_guide.md` §9）。
- 5010 / 5011 已在本机用模拟板跑通；换端口前先 `Get-NetUDPEndpoint` 查占用（pose6d 的 5001、6001 被 NI 服务占着）。

### 3.3 与 v0 的兼容和迁移

| 组合 | 结果 |
|---|---|

## 4 验证计划

只在真板上验收（用户 09-26 定"等板子回来再做"）：模拟板上测出的数不能写进报告，拔线验收与六项指标都要在真链路上测，所以不做模拟板用例。09-25 草案的 D1～D7、评审时加的 D8 / D9 与随机丢包注入都删去，其中要在真板上做的检查并入 §4.2。

### 4.1 指标验收（真板）

| 指标 | 怎么测 | 通过条件 |
|---|---|---|
| RTT / 单向时延 | 空闲与整景运行时各记 60 s | 给出分位数 |
| 有效吞吐 | 整景运行均值；完成后整幅 ROWREQ 测上限 | 运行均值 ≈ 4 B × 像素速率，两者互相印证；上限单列 |
| 丢包率 | 整景不拔线跑一次；§4.2 第 1 条拔线时再记一次 | 不拔线：两端交叉核对之差 ≤ 在途包数（直连应为 0～1）；拔线：断线窗口内的缺口单列为"断线丢包" |
| 错误率 | 脚本向板卡与地面站各发 100 包坏 magic、坏长度、未知类型 | 两端格式错误计数各 +300 |
| 重传率 | 同丢包率的两次运行 | 不拔线应为 0；拔线时命令重发与补传各有值 |
| 指令超时率 | 不拔线连发 1,000 条命令；另拔一次线，期间点一次停止 | 不拔线为 0；断线期间的停止计一次超时，恢复后对账重发、板卡停下，界面不提前显示"已停止" |
| 断线恢复时间 | 拔线 3 次 | 每次有值，报 min / 中位 / max |

### 4.2 功能验收（真板，E2 完成标准）

板子回来、C3b（lwIP 互通）通过后：

1. LongKou 整景运行中拔网线 30 s 再插回：DP 上进度不停；地面站结果与不拔线的一次逐像素相同（板上是整数路径，应逐位一致）；断线日志 1 条，检测延迟 ≤ 1.25 s，恢复时间有值。
2. 断线跨过任务结束（区域任务，拔线盖住完成时刻）：恢复后补齐才判完成，不出现"完成但缺像素"。
3. 整景运行中探查 5 个像素，其中 1 个用另一个权重版本：每次都回 LOGITS，类别与 PC 源一致（并列像素单列），整景结果不受影响。
4. 权重校验：脚本下发一次整包 CRC 错的包，板卡回 code 1、在用版本不变；再正常下发并 WACT，STATUS 的 wcrc 随之改变。
