## 5 目标系统架构

### 5.1 PL：整网引擎（一个 IP）

- 一个 IP 包下整条推理链（09-23 D1 评审定，细节与数值契约见 `docs/engine_arch.md`，契约 v2）：从 DDR 立方体取 7×7 窗 → patch 归一化 → embed → 12 层（归一化、Q/K/V 投影、6×6 注意力、残差、MLP）→ 分类头 → 每像素类别 + 置信度。
- 权重包 `weights_engine.bin`（投影因子 289 KB + embed 表 + 分类头，int16 版 481 KB）一次装入、全部驻片上；可编译成双库，后台装载、调用边界切换。
- 投影核并行度按编译参数分档：int16 版目标 E2（mode3 每拍 14 个位置，≈950 DSP），退路 E1（7 个位置，476 DSP）；int8 版目标 E2（双乘打包，476 DSP），冲刺 E3。片上同时持有 P 个 patch 轮转，P 为编译参数（int16 E2 约 4），P ≥ 3 后吞吐不再随 P 增加。
- 数值：片上激活 18 位 Q5.12（int16 版，记 W16A18）/ Q3.4（int8 版，W8A8，权重 QAT）；归一化、注意力（精确整数 scores + 查表 softmax + 整数 ctx）、残差、前端、分类头全部整数化，PC 参考到板上五级逐位，一直到类别与置信度。
- PS↔PL 接口：输入立方体行段坐标（M3b）或 PS embed 后的 int16 块（M3a / 调试）；输出每像素类别 + 置信度（4 B），单点探查输出全部 logits，调试输出逐层块。

### 5.2 PS：裸机 standalone（A53 核 0）

- FatFs 读 SD：立方体（float32，见 §14）、各景权重文件、真值（仅用于独立评测，不进入推理或业务判断）。
- 取窗 + patch 归一化：M1 / M2 / M3a 路径由 PS 复刻 preprocess.patch_tensor（torch ddof=1，float32，7020 块模式已有实现）；M3b 起移入 PL（`docs/engine_arch.md` §3.6），PS 只给行段坐标。
- lwIP UDP：向地面站发分类行和状态；收命令（区域、切景、权重块）。
- 不用 Linux：VCU 是唯一需要 Linux 的模块，本方案不用 VCU。
- 后处理分工：标签与 softmax 最大值由 PL 分类头给出（M3 起；M1 / M2 由 PS 算），PS 按行打包；行程编码作为可选传输优化，压缩大小须实测。PC 做连通域与地块统计，将低置信或类别不一致区域标为待核查，详见 §15。最大 softmax 值只是模型分数，不直接等于正确概率。
- 四核分工（Vitis 多核裸机工程，W2 起）：核 0 调度 PL（M3b 前还有取窗与 embed）；核 1 后处理与打包（M3 前还有 softmax / argmax）；核 2 lwIP 与协议；核 3 DP 帧缓冲绘制与统计。报告画核间分工图。
- 板载监视：SYSMON 读芯片温度与电压；12 V 输入串功率计取整板功耗，界面显示每像素焦耳。按键切景、LED 指示运行阶段。
- 板载资源定位：整景立方体（int16）放 PS DDR，PL 引擎经 HP 口自取窗（M3b）；PL 侧 DDR4 1 GB 要加 MIG，本方案不用；PL 网口预留传感器接入（报告说明，不实现）。

### 5.2a DP 机载监视器

- 定位：对应真实无人机上的机载调试口。回答"算在哪"：画面由 PS 直接从 DDR 绘制，不经网络，拔网线仍在跑。
- 内容：逐行着色的分类图、进度条、像素计数、ms/像素、温度、功耗。只显示不交互，一张 1080p 帧缓冲。
- 显示器：DP 接口的普通桌面显示器或便携屏；HDMI 屏需 DP 转 HDMI 有源线。不是 LCD 排线屏。
- 驱动：PS 侧 DisplayPort 控制器裸机驱动 `dppsu` + DPDMA，Xilinx 有 standalone 例程；W1 验证能否出画面，出不了则退化为串口进度。

### 5.3 地面站（PC，Python）

- 真彩色合成底图；逐像素着色随推理进度刷新；真值图切换；框选区域；作物面积统计表；速度、带宽、延迟、功耗面板；权重下发按钮。
- 决策层展示（W4）：种植面积、地块台账、置信度热力图与建议补采样区域、待核查斑块列表。产量估算仅在有依据的单产数据下作为可选估算；两套权重的结果差异只称模型对比，不作为真实多期农情变化。
- 链路实测面板：实时字节数对比"立方体 / 分类图 / 权重包"，断线期间板上继续处理、恢复后补传。
- 复用 serial_block_view.py 与 udp_frame_view.py。

### 5.4 数据流

1. SD 卡 → DDR：当前景立方体与权重包一次读入（M3b 用 int16 的 `cube_i16.bin` ≤248 MB；M1～M3a 用 float32 立方体），各 clean 一次；引擎装载权重包约 0.3 ms。
2. PS 按地面站给的区域逐行给 PL 引擎下发行段（行号、起始列、长度）（M3b）；M3b 之前由 PS 取窗、归一化、embed 后送块。
3. PL 引擎自取窗，跑 12 层与分类头，每像素类别 + 置信度写回 DDR。
4. PS 按行打包 UDP 发地面站、画 DP；地面站着色。
5. 权重下发：地面站 → UDP 分块 → PS 写 SD 与 DDR → 重载 IP 权重（双库编译时后台装载、行边界切换）。

### 5.5 运行模式（09-22 定）

板子同一时刻只跑一个任务；地面站命令 = {模式, 景, 参数, 任务号}，新命令在下一批 patch 边界抢占旧任务。性能档（E5 时钟三档）与模式正交，任何模式下可切。

| 模式 | 触发 | 板子做什么 | 回传 | 地面站显示 | 用途 |
|---|---|---|---|---|---|
| 整景巡检 | 上电自动 / 地面站"整景" | 按推扫顺序逐行扫全景 | 每行类别 + 置信度 | 分类图逐行长出，DP 同步；结束出面积表、待核查列表，可触发打印 | "落地即出图"主叙事，演示第 1 步 |
| 区域识别 | 评委画框 | 只算框内像素 | 同上 | 框内涂色、进度与预计剩余、面积表、与 PC 参考一致率 | 评委交互，演示第 3 步 |
| 单点探查 | 点击一个像素 | 算 1 个 patch | logits 全量 + 置信度 | 该像素光谱曲线、7×7 窗、logits 柱状图、类别、PC 参考 | 解释"模型看到了什么"，几乎零耗时，答辩利器 |
| 评测 | 地面站"评测" | 跑固定测试划分的全部标注像素 | 类别 | OA/AA/Kappa、与 PC 定点一致率、max\|dlogit\| | 报告数据来源，不叠业务图层 |
| 对比赛跑 | 地面站"赛跑" | 与笔记本 CPU 同时算同一区域 | 同区域识别 | 两条进度条 + 两个功率读数并排 | 加速比与能效可视化 |
| 复测 | 权重下发后自动 | 用新权重重跑上次区域 | 同区域识别 | 前后分类图并排、变化像素高亮、独立测试集前后指标 | 闭环演示第 6 步 |

- 切景与性能档是参数不是模式；切景触发权重重载（D2+ 双缓冲则不停机）。
- 每种模式的命令、回传包格式在 `docs/protocol.md`（E2）里各占一节；地面站每种模式一个面板（F2）；演示脚本 §9 每步注明模式。
- 单点探查是新增项，成本最低：PS 已有单 patch 路径（7020 串口 1），地面站只多画一条光谱曲线和一个柱状图。

## 6 性能目标

| 口径 | 7020 现状 | ZU5EV 保守（int16 E1 @150 MHz） | ZU5EV 目标（E2 @200 MHz） |
|---|---:|---:|---:|
| 每像素 | 24.3 ms | 0.75 ms | 0.28 ms |
| 64×64 块（4096 像素） | 100 s | 3.1 s | 1.2 s |
| 龙口整景 550×400 | 89 min | 2.8 min | 62 s |

估算依据（09-23 按 D1 改）：`docs/engine_arch.md` §4.6，每像素 = 12 层 × 4 投影 × 6 token × 每 token 拍数（E1 378、E2 189），另加约 3% 开销；int8 版 E2 拍数相同、投影核 DSP 减半，E3 约 0.19 ms @200 MHz。**以 Vivado 实现和板上实测为准。**

里程碑：

- M1 基线：v1.4 IP 原样在 ZU5EV 上裸机跑通（预期只靠时钟和 A53 快 2～3 倍）。
- M2 投影核（整网引擎 PROJ 模式）：权重驻片上 + 多 patch 批处理，注意力仍在 PS。
- M3（必做）整网进 PL：M3a 输入 PS embed 后的块，12 层 + 分类头在片上；M3b 前端也进 PL，PS 只给行段坐标、收类别 + 置信度。
- M4（必做，09-23 改）int8 版：同一源码 int8 编译，QAT 权重，DSP 双乘打包，与 int16 版并排报告。

## 15 结果的用途与闭环（2026-09-21 定）

板子只出分类图与置信度图；分析在地面站；闭环在地面站与农艺师之间。

### 15.1 地面站分析（PC Python，像素统计 + 连通域，W3～W4）

| 分析 | 输入 | 输出 | 用途 |
|---|---|---|---|
| 种植结构统计 | 分类图 × 地面分辨率 | 各作物面积、占比、产量估算（公开单产经验值，标来源） | 作物普查 |
| 地块台账 | 分类图 + 独立提供或人工绘制的地块边界 | 每块地主栽作物、面积占比、类别混杂比例 | 种植登记与人工核查辅助，不直接作补贴认定或保险定损 |
| 异常斑块 | 分类图 + 置信度图 | 与主栽不一致或低置信的连通区，带坐标与面积 | 现场核查（措辞"待核查"，非病害诊断） |
| 补采样建议 | 置信度图 | 低置信区域列表 | 下一架次与地面采样规划 |
| 多期变化（有数据后可选） | 配准后的不同时期观测及其分类结果 | 变化候选图 | 无第二期数据时不实现；不同权重在同一图上的差异仅作模型对比 |

### 15.2 闭环六步

1. 采集：无人机推扫得立方体（演示由 SD 卡代替）。
2. 板端分类：板子输出分类图、置信度图和任务状态，下传地面站；可选行程编码。
3. 地面分析：15.1 各项。
4. 人的决策：农艺师点开异常斑块，判断误分或真异常，标注真实类别。
5. 模型更新：核查标注加入训练集，PC 更新模型并在固定独立测试集上验证，记录时间与精度，再导出权重包。
6. 权重下发：地面站发送带版本与校验信息的权重，板子验证后重载并复测；保留旧版本以便回退。

演示时从独立的核查/训练区域取预留标注，走 4→6 一遍，报告明确其模拟来源。新标注不能与测试集混用，更新后不保证所有误分消失；训练来不及时，可演示事先训练并验证的新版本下发，必须标明是版本更新演示，不宣称现场训练。

业务边界：地面分辨率和投影关系有效时才计算地面面积；类别真值图不等于真实地籍边界，且不进入业务分析输入；无地理参考时只报告行列坐标。低置信与类别不一致只触发待核查任务，不能诊断病虫害。产量估算需要独立单产依据，不作为本模型预测能力。

### 15.3 板子额外工作

板端实现置信度输出、任务与权重版本管理、传输校验及可选行程编码；PC 完成连通域、台账、核查与模型更新流程。分别验证数值、协议与失败恢复，工期以接口原型实测评估，不将半天估计作为交付保证。

### 16.5 本项目的验证口径

- 应用演示明确采用公开无人机数据的板端回放。框选、分类、统计、核查与权重更新均记录实际任务和模型版本，不以回放界面证明已经实飞。
- 精度验证固定训练/验证/测试划分，模型更新不使用测试真值；地块业务边界独立输入。多景适配不自动等于跨景泛化。
- 定点整数算子在相同规范下逐位比较；涉及浮点运算时预先规定数值容差，并同时报告 logits 误差与标签一致率，不把标签一致写成全网数值逐位一致。
- 性能测量注明输入大小、批量、时钟、预热和计时范围；原始数据读取、板端推理、后处理与传输可分项，同时给端到端时间。峰值 DSP 理论值不能替代板上性能。
- 整板功耗用输入端测量，SYSMON 温度/电压不能代替功率计；能效注明是否包含启动、数据加载、空闲及外围设备。
- 链路对比说明原始立方体编码、分类图、置信度、统计、协议头和重传的字节数，以及冷启动底图是否计入；不能只用分类标签的理论大小宣称整系统压缩倍率。
- 开源发布与指南符合性检查分别安排；当前模型训练、PC验证、技能包及板前平台构建已有证据，详见 `report/evidence.md`。ZU5EV上板验收、干净环境复现及公开发布尚未完成。
